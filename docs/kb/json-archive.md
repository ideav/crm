# JSON-архив таблицы — выгрузка и загрузка одним документом

> Часть базы знаний Integram. Индекс: [docs/kb/README.md](README.md)

## На пальцах (для человека)

Архив таблицы — это её метаданные (колонки, типы, ссылки) вместе с данными в одном файле.
Он нужен, чтобы перенести таблицу в другую базу, снять копию перед опасной правкой или
залить подготовленный набор записей.

Форматов два, и делают они одно и то же:

- **BKI** — построчный текст: колонки разделены `;`, части колонки — `:`, значения
  мульти-ссылки — `,`. Значение с разделителем внутри экранируется обратной косой.
- **JSON** — тот же состав, но структурой документа. Экранирование не требуется: значение
  с `;`, `:`, запятой и переводом строки едет как есть. Выгрузка (v2) — шапка с отступами
  и по одной записи на строку: файл читается глазами, грепается и сравнивается построчно.

Кнопки — на панели таблицы: «Экспорт BKI», «Экспорт JSON», «Импорт архива». Импорт один на
оба формата: он смотрит на первый символ файла (`{` — JSON, `DATA` — данные без метаданных,
иначе — заголовки BKI) и разбирает соответственно.

## Операции

Экспорт (той же формой, что рисует таблицу; фильтры и сортировка страницы применяются):

```
POST /{db}/object/{tableId}?json_export=1            → data_export.json
POST /{db}/object/{tableId}?json_export=1&gzip=1  → data_export.json.gz
POST /{db}/object/{tableId}?bki=1             → data_export.bki
```

Импорт — как у BKI, полем `bki_file`, формат определяется по содержимому:

```
POST /{db}/object/{tableId}?JSON&import=1
multipart/form-data:  bki_file=<файл>, token=<token>, _xsrf=<xsrf>
```

Права — **WRITE+EXPORT** на тип (или admin), предел размера файла — 8 МБ, предел времени —
300 c. Остальное поведение импорта (upsert по ключу уникальности, разрешение ссылок по
именам, `F_U` для подчинённой таблицы) — общее с BKI, см. [import.md](import.md).

## Документ

Текущая версия формата — **2** (issue #4983): шапка — с отступами, каждая запись `rows` —
одной строкой файла; в шапке поле `readme` — как читать строки.

```json
{
    "format": "integram-archive", "version": 2,
    "readme": "rows: одна запись на строку; ключ val — значение главной колонки, остальные ключи — реквизиты по алиасам из types; отсутствующий ключ = пусто",
    "db": "atex", "exported": "2026-10-14T10:00:00+03:00",
    "table": 1076,
    "types": {
        "1076": {"id": 1076, "name": "Заказы", "base": "SHORT", "unique": true, "reqs": [
            {"id": 1077, "kind": "field", "name": "Дата",   "base": "DATE", "attrs": ":KEY:", "key": true},
            {"id": 1078, "kind": "ref",   "name": "Цвет",   "type": 2001, "target": "Цвет", "multi": true},
            {"id": 1079, "kind": "arr",   "name": "Строки", "type": 1090, "target": "Строки заказа"}
        ]},
        "2001": {"id": 2001, "name": "Цвет", "base": "SHORT", "reqs": []}
    },
    "rows": [
        {"val": "Заказ №1", "Дата": "2026-09-01", "Цвет": ["Красный", "Синий"]}
    ]
}
```

- `table` — id таблицы, чьи записи лежат в `rows`; `types` — она сама и все типы, на которые
  она ссылается.
- `reqs[].kind`: `field` — обычный реквизит (`base` — базовый тип: `SHORT`, `DATE`,
  `DATETIME`, `NUMBER`, `MEMO`, `BOOLEAN`…), `ref` — ссылка, `arr` — подчинённая таблица.
- У ссылки `name` — подпись колонки (алиас из `attrs`, иначе имя целевой таблицы), а
  `target` — **всегда имя целевой таблицы**. При загрузке в другую базу id свои, поэтому
  колонка сводится по `target`, а не по `type`.
- Ключ значения в записи — **короткое имя колонки**: алиас, иначе имя (у журнала колонка
  называется «Журнал.Сессия», алиас у неё «Сессия» — ключ в записи `Сессия`). Полное имя
  остаётся в `types`; у колонок, где короткое имя расходится с полным, рядом лежит
  `"alias"`. Одноимённые колонки уточняются `#id`; принимаются также полное имя колонки и
  голый id.
- Каноничное целое (без ведущих нулей, до 15 цифр) выводится **числом**, всё остальное —
  строкой как есть (коды, `"007"`, даты): обратная загрузка не искажает значения.
- Пустые значения ключа не получают: ключа нет = колонка пуста.

Значения идут как есть, без экранирования. Ссылки задаются **именами целевых записей**,
мульти-ссылка — массивом имён (так же, как в сокращённом формате BKI).

| В записи | Что происходит при загрузке |
|---|---|
| ключа нет | колонка не трогается |
| `null` | значение очищается (в BKI это `" "`) |
| `""` | записывается пустая строка |
| `"val": ""` (у записи) | запись удаляется по ключу уникальности |

При загрузке запись v2 нормализуется к внутреннему виду v1 (`JsonArchiveNormalize`):
обёртка `fields`, полные имена колонок, значения строками. **Документы v1** — записи
`{"id": ..., "val": ..., "fields": {...}}`, все значения строками — импорт принимает
как есть.

Подчинённые таблицы (`kind: "arr"`) в `rows` не вкладываются — в документе они только
объявлены. Записи подчинённой таблицы архивируются отдельным документом и грузятся с
`F_U=<id записи-родителя>`, как и в BKI.

## Сведение колонок при загрузке

Идентификаторы архива в целевой базе заняты чужими записями, поэтому каждой колонке архива
ищется местная пара — по порядку:

1. **id + вид + форма** — тот же реквизит на своём месте (обычный случай: архив грузится
   обратно в ту же базу);
2. **имя + вид + форма** — колонка переехала на другой id;
3. **только `target`** (для `ref`/`arr`) — ссылка подписана другим алиасом, но ведёт в ту же
   таблицу.

«Форма» — это базовый тип для обычного реквизита и целевая таблица для ссылки. Совпадение
имени при разном базовом типе парой НЕ считается: `Дата:DATE` и `Дата:DATETIME` — разные
колонки. Колонка архива, которой пары не нашлось, **создаётся** (реквизит, а для ссылки —
при необходимости и целевая таблица со строкой-посредником). Найденные пары фиксируются:
значения строк раскладываются по местным колонкам уже по привязке, а не подбором по имени —
поэтому переименованная в целевой базе колонка получает своё значение, а не сведённая не
получает ничего.

Разбор этих правил — `include/json_archive.php` и `include/import_reconcile.php`; поведение
держат `experiments/json-archive-4968.test.php`, `experiments/json-archive-4983.test.php` (v2: одна запись на строку, короткие имена, нормализация) и
`experiments/import-reconcile-4968.test.php` (в гейт заходят через одноимённые `.test.js`).

## Грабли

- **Симптом:** после выгрузки и загрузки обратно в значении пропал кусок текста: было
  `https://host/?a=1%3Bb`, стало `https://host/?a=1;b` → **Причина:** разбор BKI прятал
  экранированные разделители в маркеры `%3B`/`%3A`/`%2C`/`%5C` — обычный текст, который
  встречается в данных (URL-кодирование), и обратная подстановка не отличала свой маркер от
  данных → **Фикс:** маркерами служат управляющие символы `\x01..\x04`
  (`include/delimiters.php`), которых в значениях полей не бывает; в JSON-архиве
  экранирования нет вовсе. *(15.09.2026, issue #4968)*
- **Симптом:** значения колонки даты приехали в колонку даты-времени (или наоборот), обе
  называются одинаково → **Причина:** колонка архива искала местную пару по ПРЕФИКСУ подписи,
  а базовый тип в подписи стоит последним: `Дата:DATE` — префикс местной `Дата:DATETIME` →
  **Фикс:** совпадением считается равенство подписи либо её продолжение двоеточием (дальше
  идут только атрибуты) — `ImportMatchLocalReq`. *(15.09.2026, issue #4968)*
- **Симптом:** повторная загрузка того же BKI каждый раз заново заводит ссылочный реквизит →
  **Причина:** подпись ссылки склеивалась без разделителя (`ref:1079` + `9001` =
  `ref:10799001`) и не совпадала с местной `ref:1079:9001` → **Фикс:** `ImportReqSignature`
  собирает подпись через двоеточие и подставляет уже найденные замены id.
  *(15.09.2026, issue #4968)*
- **Симптом:** импорт падает с «Тип N отсутствует в мета-данных» на колонке-ссылке, заданной
  как `ID:Значение` → **Причина:** целевой тип ссылки искался в `local_struct` по id
  РЕКВИЗИТА, а запись там есть у строки-посредника → **Фикс:** целевой тип берётся из
  `$GLOBALS["refs"][<реквизит>]`, куда его кладёт `constructHeader`; в разрешении конфликтов
  туда же пишется целевой тип, а не строка-посредник. *(15.09.2026, issue #4968)*
- **Симптом:** после импорта в базе два типа с одинаковым на вид именем, а в имени нового —
  невидимые символы → **Причина:** имя из файла идёт экранированным, а разбор строки
  заменяет экранированные разделители маркерами; поиск существующего типа шёл по такому
  имени и ничего не находил → **Фикс:** имя приводится к виду, в каком лежит в базе
  (`ImportDbName`), до сравнения и до вставки. *(15.09.2026, issue #4968)*
- **Симптом:** в JSON-архиве у ссылочной колонки с составным ключом уникальности значение с
  обратной косой перед `:`/`;`/`,` приезжает изменённым → **Причина:** разрешение ссылки по
  составному ключу (`UniqueKeyUnmaskRefValue`) снимает экранирование внутри, а в JSON
  значение уже неэкранированное → **Фикс:** не ставить обратную косую вплотную к этим
  символам в ключевых ссылочных значениях; для остальных колонок значение едет как есть.
  *(15.09.2026, issue #4968)*
