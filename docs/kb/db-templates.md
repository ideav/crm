# Шаблоны баз: фиксация, модерация, создание базы из шаблона

## На пальцах

Любую базу можно сделать шаблоном. Владелец базы в меню файлов (`dir_admin` → «Шаблон базы»)
задаёт имя шаблона и нажимает «Зафиксировать версию». Сервер снимает копию данных и файлов базы.
Пользователи, пароли и токены в копию не попадают. Версия уходит на модерацию. После одобрения
модератором шаблон появляется в Личном кабинете в списке «Шаблон» при создании базы, и новая база
создаётся из этой копии.

Шаблон меняется только новой зафиксированной версией. Правки исходной базы после фиксации в шаблон
не попадают, пока владелец не зафиксирует следующую версию и модератор её не одобрит. Базы,
созданные раньше, не меняются.

## Справочник

### Хранилище

`templates/custom/my/db_templates/`:

| Путь | Что |
|---|---|
| `registry.json` | реестр: `{id: {title, descr, source, author, versions: [{ver, status, created, by, note, moderated}]}}` |
| `<id>/<ver>/data.dmp.zip` | дамп базы в формате `Backup_dump` без пользователей и секретов |
| `<id>/<ver>/code.zip` | файлы базы в формате `Code_backup`: корень `templates/custom/<база>`, фронт в корне `download/<база>`, подпапки `download/<база>` целиком |

Что не попадает в дамп (`Tpl_secret_ids`, `index.php`): записи «Пользователь» (t=18, up=1);
реквизиты записей «Пароль» 20, «Токен» 125, «xsrf» 40, «Secret» 130, «Активность» 124,
«Попытки входа» 301; всё, что лежит под ними или ссылается на них (t = id такой строки).
Реквизиты этих типов в схеме (строка под типом) остаются.

### Статусы версии

`pending` (на модерации) → `approved` | `rejected`; `pending` или `approved` → `withdrawn` (снята).
В ЛК разворачивается последняя `approved`-версия (`Tpl_current`). Если её снять, разворачивается
предыдущая одобренная.

### Кто что может

| Действие | Кто | Где |
|---|---|---|
| Зафиксировать версию | владелец базы (пользователь с именем базы) или супер-админ сервера | в своей базе |
| Системное имя из `TEMPLATES` (`ru`, `cm`, …) | только супер-админ сервера | в базе-источнике |
| Одобрить, отклонить | модератор: супер-админ, владелец базы `my`, логины из `INTEGRAM_TPL_MODERATORS` (`:логин:логин:`) | в базе `my` |
| Снять версию | модератор (в `my`) или владелец базы-источника (в ней) | |

Имя шаблона: `^[a-z][a-z0-9]{1,14}$`, не `my`. Имя принадлежит базе, которая зафиксировала первую
версию: другая база его не займёт.

### API

| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /<db>/_tpl_list?JSON` | — | `{templates: [{id, title, descr, author, ver, source?, versions?}], moderator: 0/1}` |
| `POST /<db>/_tpl_publish?JSON` | `id`, `title`, `descr`, `_xsrf` | `{result: "ok", id, ver, status: "pending"}` или `{error}` |
| `POST /<db>/_tpl_status?JSON` | `id`, `ver`, `status` (`approved`/`rejected`/`withdrawn`), `note`, `_xsrf` | `{result: "ok", id, ver, status, current}` или `{error}` |

`_tpl_list` в базе `my` обычному пользователю отдаёт одобренные шаблоны без истории версий,
модератору — все с версиями. В базе-источнике её владельцу — его шаблон с версиями.

Создание базы: `POST /my/_new_db/?JSON&db=<имя>&template=<id>`. `newDb()` сначала ищет одобренную
версию `<id>` в реестре (`Tpl_deploy`: `CREATE TABLE <база> LIKE ru`, строки из дампа, файлы из
архива), иначе берёт системный шаблон-таблицу из `TEMPLATES`, иначе `ru`. Владельцу новой базы
назначается роль admin (`Restore_admin_role`: найти или создать).

Интерфейс — `js/db-templates.js`: `initDirAdmin` (меню файлов), `initCabinet` (выбор шаблона и
панель модерации `#tpl-moderation` в `templates/my/main.html`).

## Грабли

**Файлы в подпапках `templates/custom/<база>` в шаблон не попадают.** `Code_backup` берёт только
корень этой папки: подпапки там служебные (`backups`, `logs`). Шаблоны рабочих мест держать в корне.

**Шаблон одобрен, а в ЛК его нет в списке.** Список ЛК читает `GET /my/_tpl_list?JSON`. Шаблон с
версиями только в статусах `pending`, `rejected`, `withdrawn` в нём не виден: проверить статус в
панели модерации или в `registry.json`.
