# Колонки-кнопки: ссылка, промпт ИИ, формула, запрос

## На пальцах

Колонка базового типа **7 (BUTTON)** показывается в таблице как кнопка. Что делает кнопка,
записано в модификаторе колонки — JSON-описании действия. Типов четыре:

- **Ссылка** — переход по адресу, в новой вкладке или в этой же.
- **Промпт ИИ** — текст уходит ИИ-агенту базы и выполняется под учёткой пользователя
  (того, кто нажал, или заданного в настройке «Выполнять от имени»). Агент делает то, что
  написано в промпте.
- **Формула** — значение считается по полям строки.
- **Запрос** — выполняется запрос (отчёт) базы по имени, результат — первое значение первой строки.

У промпта, формулы и запроса есть галка «Записывать результат в поле записи». С ней результат
сохраняется в значение этой колонки у записи, и вместо кнопки в ячейке видно значение с кнопками
«Пересчитать» и «Удалить результат». Без неё результат показывается на месте (у промпта — в окне)
и никуда не пишется. Если поменять настройку колонки, записанные результаты остаются как были.

**Когда выполняется действие** — галки «Запуск»:

| Запуск | Событие | Где выполняется |
|---|---|---|
| по нажатию | `PRESS` | браузер (по умолчанию) |
| при показе | `READ` | браузер: пустая ячейка заполняется при показе таблицы; с галкой «Пересчитывать при каждом показе» значение считается всегда и не записывается |
| при создании | `CREATE` | сервер, после создания записи |
| при изменении | `UPDATE` | сервер, после изменения записи |
| при удалении | `DELETE` | сервер, по значениям удалённой записи |

Создание, изменение и удаление ловит сервер, поэтому триггер срабатывает при любом способе
записи: таблица, карточка, API, пакетная запись, импорт через эти команды. Колонка без
«по нажатию» кнопки не показывает — только значение. Ссылка запускается только нажатием.

«Условие (формула)» — действие выполняется, только если формула истинна (например,
`{Статус} = "Оплачен"`). «Выполнять от имени» — логин пользователя, под которым выполняется
действие (запрос, промпт, запись результата); пусто — текущий пользователь.

Настраивается действие в окне «Редактирование колонки» (шестерёнка колонок → колонка): при
базовом типе «Кнопка» появляется блок «Действие кнопки». Массово: включить выбор строк
(чекбоксы), отметить строки — на панели таблицы появится кнопка колонки с числом строк, она
выполняет действие по отмеченным строкам по очереди (только у колонок с запуском по нажатию).

В шаблонах (адрес, промпт, формула, параметры запроса, условие) доступны:

| Подстановка | Значение |
|---|---|
| `[ID]` | id записи |
| `[VAL]` | значение первой колонки записи |
| `{Название колонки}` | значение поля этой строки (по отображаемому имени колонки, регистр не важен) |

## Справочник для агента

### Формат модификатора

Модификатор (attrs) реквизита — JSON; действие лежит под ключом `action`, остальные ключи
(`required`, `alias`, …) не трогаются:

```json
{"required":true,"action":{"type":"formula","formula":"ROUND({Цена} * {Количество}, 2)","write":true,"label":"Сумма","on":["CREATE","UPDATE"]}}
```

| type | поля | |
|---|---|---|
| `link` | `url`, `newTab` (по умолчанию `true`) | `url` дублируется в `default` модификатора — сервер подставляет в него `[ID]`/`[VAL]` для карточки записи и API |
| `prompt` | `prompt`, `write` | |
| `formula` | `formula`, `write` | |
| `query` | `query` (имя или id запроса), `params` (строка `FR_Колонка=[ID]&TO_…`), `write` | вызов `report/{query}?JSON_KV&{params}` |

Общие ключи (кроме `link`, у которой только `label`):

| ключ | значение | по умолчанию |
|---|---|---|
| `label` | подпись кнопки | без подписи — только значок |
| `on` | массив событий из `PRESS`, `CREATE`, `UPDATE`, `DELETE`, `READ`; строка `"CREATE,UPDATE"` тоже принимается | `["PRESS"]` |
| `recompute` | `true` — при `READ` считать при каждом показе, сохранённое значение не показывать и не писать | `false` |
| `when` | формула-условие; действие выполняется, если она истинна | всегда |
| `user` | исполнитель: id записи пользователя (таблица 18); `_d_action` принимает и логин и сохраняет id | текущий пользователь |

Ключи со значением по умолчанию в модификатор не пишутся. Колонка без `action`, но с
`default` — обычная ссылка: адрес из `default`, сервер уже подставил `[ID]`/`[VAL]`.

### Команды

```
POST /{db}/_d_action/{reqId}?JSON
  _xsrf=…&action={"type":"prompt","prompt":"Опиши {Название}","write":true,"on":["CREATE"]}
```

- Права — как у прочих `_d_*` (редактирование типов).
- `action` пустое — снять действие. Ошибка «Неверное описание действия кнопки: …» называет
  причину: не JSON, неизвестный `type`, неизвестное событие, ссылка с событием кроме `PRESS`,
  пользователь из `user` не найден.
- Поля, не относящиеся к типу, отбрасываются; строки обрезаются до 8000 символов.
- `_d_attrs` (редактор структуры) сохраняет `action`, меняя только стандартные флаги.

Запись результата из браузера: `POST /{db}/_m_set/{recordId}?JSON` с `t{reqId}=результат`;
пустое значение удаляет результат.

```
POST /{db}/_m_action/{recordId}?JSON&col={reqId}
  _xsrf=…[&nowrite=1]
```

Выполняет действие колонки на сервере от имени `user` (браузер так не умеет; без `user`
браузер выполняет действие сам). Ответ `{"result":"…","written":true}` или для промпта
`{"job":{…}}` — браузер опрашивает `GET /{db}/ai/agent?job=ID`, задача видна нажавшему.
`nowrite=1` — не записывать (показ с пересчётом). Требует права на чтение записи.

### Триггеры на сервере (CREATE / UPDATE / DELETE)

Код — `include/button_triggers.php` (движок) и блок `<button-triggers-866>` в `index.php`.

- Срабатывают после успешных `_m_new`, `_m_set`, `_m_save` (копия записи — это `CREATE`),
  `_m_del` и каждой операции `_m_batch`.
- `UPDATE` — если изменилась колонка, на которую ссылается действие (`{Колонка}` в формуле,
  промпте, параметрах, условии; `[VAL]` — первая колонка). Действие без ссылок срабатывает на
  любое изменение, кроме своей колонки. Изменения определяются сравнением записи до и после.
- `DELETE` — по значениям записи до удаления; `write` не действует (писать некуда).
- Запросы с `client=ai` (собственные записи ИИ-агента) триггеры не запускают.
- Сначала отвечаем пользователю, потом работаем: при запросе синхронно проверяются только
  исполнитель, условие, формула (пробное вычисление) и лимит промптов — их отказы приходят
  в `warnings` ответа. Запись результата, запрос и промпт выполняются после отправки ответа
  (`fastcgi_finish_request`), по порядку колонок; каждое действие перечитывает запись и видит
  результаты предыдущих.
- **Формула** — на сервере тем же вычислителем, что в браузере (порт один к одному; общие
  векторы — `experiments/button-formula-vectors.fixture.json`). `TODAY()` — дата сервера с
  поправкой пользователя (`tzone`).
- **Запрос** — отдельным HTTP-запросом к себе `report/{query}?JSON_KV&{params}&bt_chain=…` с
  токеном исполнителя. Адрес сервера — `BUTTON_TRIGGER_BASE_URL` (или
  `AI_AGENT_CALLBACK_BASE_URL`) в `include/connection.php`, иначе `https://{Host запроса}`.
- **Промпт** — задача ИИ-агенту под токеном исполнителя, контекст
  `{page:"trigger", table_id, object_id, event, column}`. Ответ приходит в callback
  (`/{db}/ai/agent/callback`), очищается от обрамления ```` ``` ```` и пишется в колонку от имени
  исполнителя с пометкой ИИ. Задачи кнопок хранятся отдельно от задач чата
  (`ai_agent_trigger_jobs_{db}.json` во временном каталоге сервера). Оплата ИИ проверяется
  как в чате; не оплачено — промпт молча пропускается (строка в журнале).
- **Лимит** — не больше `BT_PROMPT_HOURLY_CAP` (60) промпт-задач триггеров в час на базу;
  сверх лимита — предупреждение в ответе и в журнале.
- **Цепочка** — запись триггера запускает `UPDATE`-триггеры других колонок. Цепочка
  (id колонок) общая для всех записей запроса и уходит дальше параметром `bt_chain` и в
  контекст агента: колонка не срабатывает дважды в одной цепочке, длина цепочки — не больше
  `BT_MAX_DEPTH` (3).
- **Журнал** (`logs/{db}_log.jsonl`, `{db}_sql.jsonl`): запись триггера — логин исполнителя
  (`ivanov`), запись ответа агента — `ivanov~ai`; служебные строки — с префиксом `[button]`.

### Исполнитель (`user`)

Тот, кто может добавить кнопку, владеет базой: ограничений на выбор исполнителя нет, кроме
прав `_d_action`. Исполнитель хранится id записи «Пользователь» (логин можно переименовать).
Удалён (записи нет) или закрыт (нет роли — такой пользователь не входит в базу) — действие не
выполняется, предупреждение в ответе и журнале; запись пользователя сохраняется. Нет токена —
выпускается, как при входе.

### Конфликты

| # | Ситуация | Поведение |
|---|---|---|
| 1 | Запрос или промпт триггера удаляет саму запись | Ответ пользователю уже отдан. Результат в удалённую запись не пишется, остальные триггеры по этой записи пропускаются (строка в журнале). |
| 2 | Запись удалена или изменена, пока шла задача агента | Перед записью ответа проверяется, что запись есть и её тип тот же (id не занят другой записью). Если значение колонки изменилось с момента постановки задачи (поправил человек) — ответ не пишется, строка в журнале. |
| 3 | Несколько триггеров одной записи и события | Выполняются по порядку колонок; каждый пишет только свою колонку и видит результаты предыдущих. Побочные изменения запросов и промптов — в порядке их завершения, последний побеждает. |
| 4 | Запрос триггера меняет другие записи той же таблицы | Их триггеры запускаются с той же цепочкой (`bt_chain`): та же колонка не срабатывает повторно ни на одной записи, глубина ≤ 3. |
| 5 | Запись триггера нарушает уникальность или другую проверку ядра | Отказ ядра внутри записи триггера — исключение, а не `exit`; работа идёт после ответа, так что запись пользователя уже сохранена и отдана. Отказ — в журнал, остальные триггеры выполняются. |
| 6 | Триггер в `_m_batch` | События определяются по каждой операции сразу после неё, работа выполняется после ответа на весь пакет. Повтор того же события по той же записи и колонке за запрос выполняется один раз — с последним состоянием записи. |
| 7 | Исполнитель удалён, закрыт или без токена | Удалён/закрыт — триггер не выполняется, предупреждение; нет токена — выпускается. |
| 8 | Двойное сохранение — тот же триггер дважды подряд | Промпт: пока задача по этой записи и колонке в работе (до 15 минут), вторая не ставится — предупреждение. Формула и запрос: последний запуск побеждает (значение пересчитывается из текущих данных). |

### Формулы

Выражение, не JavaScript: доступны только перечисленное ниже и подстановки строки.

- Числа (`1.5`), строки в кавычках (`"текст"`), `[ID]`, `[VAL]`, `{Колонка}`. Значения полей,
  похожие на число (`1 250,5`), считаются числами.
- `+ - * / %`, `&` — склейка строк (`+` склеивает, если хотя бы одна сторона не число).
- Сравнение `= == != <> < <= > >=`, логика `&& || !`, условие `a ? b : c`.
- Функции: `ROUND(x[,n]) FLOOR CEIL ABS MIN MAX SUM AVG NUM IF(c,a[,b]) LEN UPPER LOWER TRIM
  LEFT(s,n) RIGHT(s,n) CONCAT TODAY() DAYS(до, от) ADDDAYS(дата, n)`. Даты — `ДД.ММ.ГГГГ`.

### Промпт

Из браузера сообщение уходит в `/{db}/ai/agent` (тот же агент, что у чата базы) с контекстом
`{page:"table", table_id, object_id}`. При `write` к промпту добавляется требование ответить
одним значением для поля; ответ (без обрамления ```` ``` ````) пишется в поле. Если агент
предлагает изменения на подтверждение, они подтверждаются в ИИ-чате.

### Как ИИ-чату настроить колонку по описанию

1. Найти реквизит: `metadata/{tableId}` → `reqs[]`, у колонки-кнопки базовый тип 7. Нет колонки —
   создать (`_d_req` с типом 7, см. [schema.md](schema.md)).
2. Собрать `action` по таблицам выше, проверить имена колонок в `{…}` по `metadata`. «Когда
   создают запись — заполни поле» — это `on:["CREATE"]` и `write:true`; «когда меняется
   Цена» — `on:["UPDATE"]` и ссылка `{Цена}` в действии или в `when`.
3. `POST _d_action/{reqId}` и пересказать пользователю: тип, текст промпта/формулы, когда
   запускается, от чьего имени, пишется ли результат в поле.

## Грабли

- **Симптом:** после сохранения в редакторе структуры у кнопки пропало действие. **Причина:**
  пересборка модификатора только из стандартных полей. **Фикс:** `FieldAttrsBuild` переносит
  нестандартные ключи из прежнего модификатора (`include/field_attrs.php`).
- **Симптом:** в карточке записи нет кнопки с промптом/формулой/запросом. Так и задумано:
  такие действия выполняются из таблицы; в карточке выводятся только кнопки-ссылки.
- **Симптом:** триггер с запросом ничего не пишет, в журнале «запрос …: …» с ошибкой связи.
  **Причина:** сервер не достучался до себя по `https://{Host}` (внутренняя сеть, сертификат).
  **Фикс:** задать `BUTTON_TRIGGER_BASE_URL` в `include/connection.php` — адрес, по которому
  сервер видит сам себя.
