# Дэшборд / финмодель — рабочее место `dash`
> Часть базы знаний Integram. Индекс: [docs/kb/README.md](README.md)

## На пальцах (для человека)
Рабочее место `dash` (адрес `/{db}/dash/{id}`) показывает **модель**: слева названия
строк («Выручка», «Себестоимость», «EBITDA»), сверху — периоды (кварталы, месяцы, годы),
в клетках — числа. Часть строк вводят, часть считается формулами по соседним строкам.
Одна база держит сразу несколько моделей: у каждой компании свой дэшборд, а строки и
значения помечены «Меткой» — именем компании.

Собирается модель из четырёх слоёв: **Дэшборд → Лист → Панель → Строка**, плюс у панели
есть **RG** — описание того, какие колонки рисовать (повтор по периодам, колонка суммы,
колонка единиц измерения). Числа лежат отдельно, в таблице «Значение», и связываются со
строкой модели **по имени** строки и «Метке».

Рабочее место ничего не выдумывает: и структуру, и числа оно берёт двумя отчётами —
`report/Дэшборд` (структура) и `report/Дэшборд.ЗначенияЗаПериод` (числа). **Если в отчёте
нет нужной колонки — модель молча рисуется пустой.** Так и было в finmo: колонок периода
и RG в отчёте не оказалось, и дэшборд показывал только названия строк (issue #4661).

## Схема данных (ids — из базы `finmo`, в своей базе брать из `metadata`)

| Таблица | id | Колонки (id=имя) |
|---|---|---|
| Дэшборд | 559 | 560=С, 561=По, 562=Период→«Период», 563=Лист (подчинённая 551), 565=Запустить (`dash/[ID]`) |
| Лист | 551 | 552=Панель (подчинённая 537), 554=Год, 555=Период, 556=Роль, 558=Сетка |
| Панель | 537 | 538=Строка (подчинённая 509), 539=RG (подчинённая 525), 541=Период, 542=Шапка, 543=Метка, 545=Без даты, 547=Настройки, 548=Запрос, 550=Сноски |
| Строка | 509 | 511=Уровень, 513=Стиль, 515=Формула, 517=Инициализация, 518=Ед.изм., 520=Значение, 522=Формат значений, 523=Колонка группы, 524=Метка |
| RG | 525 | 527=Тип RG→473, 529=Формат (JSON), 530=Описание, 532=Шапка, 533=Запрос, 534=Колонка группы→495, 536=Формула |
| Значение | 496 | val=число, 498=Дата, 500=Строка бюджета→493, 502=Столбец→494, 504=Ед.изм., 506=Колонка группы→495, 508=Метка |
| Тип RG | 473 | 475=**Код**, 477=Описание |
| Период | 481 | записи-справочник: «Месяц», «Квартал», «Год» |
| Квартал / Месяц / Год | 482 / 487 / 490 | С, По — границы каждого периода (`1 кв. 2024` = 01.01.2024–31.03.2024) |

Иерархия — подчинёнными записями (`up`): Лист `up`=id дэшборда, Панель `up`=id листа,
Строка и RG `up`=id панели. Справочники «Строка бюджета» (493), «Столбец бюджета» (494),
«Колонка группы» (495, «Факт»/«План») — плоские.

**Коды типов RG** (`473 → Код`) — рабочее место сравнивает именно с ними:

| Код | Что рисует |
|---|---|
| `rg` | повтор группы колонок на каждый период диапазона (основной режим модели) |
| `col` | сумма статей |
| `value` | одна колонка со значением по формуле строки |
| `formulas` | вычисления по соседним ячейкам со смещением (`[-1]`, `[-2]`) |
| `mu` | колонка с единицами измерения |
| `line` | одна колонка — сумма всех значений строки |
| `query` | колонки берутся из отчёта, указанного в RG → Запрос |

## Отчёт структуры — `report/Дэшборд`

Вызов рабочего места: `report/Дэшборд?JSON_KV&FR_modelID={id дэшборда}&period={детализация}`,
одна строка ответа = одна строка модели. **Имена колонок отчёта — это контракт** (`t100`,
«Имя в отчете»); колонка без `t100` или с галкой «Скрыть» (`t107`) в `JSON_KV` не приходит
вовсе, и рабочее место читает `undefined`.

Обязательные (без них модель без колонок или без данных):

| Колонка отчёта | Откуда | Зачем |
|---|---|---|
| `modelID` | Лист, функция `abn_UP` | фильтр `FR_modelID` — только листы этого дэшборда (скрытая) |
| `sheet`, `sheetID` | Лист (`abn_ID`) | вкладки |
| `panel`, `panelID` | Панель (`abn_ID`) | панели листа |
| `item`, `itemID` | Строка (`abn_ID`) | строки модели |
| `period` | Дэшборд → Период (или Панель/Лист → Период) | **ось периодов**: имя таблицы-словаря (`Квартал`), которую рабочее место затем читает целиком |
| `periodFrom`, `periodTo` | Дэшборд → С / По | диапазон расчёта: строка фильтра и запрос значений |
| `RG` | RG, функция `abn_ORD` | номер группы колонок панели |
| `RGtype` | RG → Тип RG → **Код** | режим отрисовки (`rg`, `value`, …) |
| `RGcolumns` | RG → Колонка группы | подколонки внутри периода («Факт», «План») |
| `formulas` | Строка → Формула | формула строки |
| `level` | Строка → Уровень | отступ строки |
| `Метка` | Строка → Метка | компания: и подпись модели, и фильтр значений |

Необязательные, каждая включает свою возможность: `rgHead` (RG → Шапка), `RGformulas`
(RG → Формула), `RGsourceID` (RG → Запрос, для `RGtype=query`), `itemsHead` (Панель → Шапка),
`panelNotes` (Панель → Сноски, Markdown), `panelSettings` (Панель → Настройки, JSON вида
визуализации), `panelFilter`, `panelQuery` (Панель → Запрос: панель питается отчётом),
`NoDates` (Панель → Без даты), `Сетка` (Лист → Сетка, плиточный режим), `itemSrcName`
(искать значения под другим именем), `value` (Строка → Значение), `MU`, `Формат значений`,
`Стиль`, `Инициализация`.

**`RGtype` брать именно «Кодом».** Колонка на сам ref (`RG → Тип RG`) вернёт название
(«Repeating group»), а рабочее место сравнивает с `rg` — колонок не будет.

## Отчёт значений — `report/Дэшборд.ЗначенияЗаПериод`

Вызов: `?JSON_KV&Fr={ГГГГММДД}&To={ГГГГММДД}`. Диапазон применяется вычисляемой колонкой
`((Дата BETWEEN '_request_.Fr' AND '_request_.To') OR Дата IS NULL)`, а сами числа
собираются `GROUP_CONCAT`-ом в колонку `value`:

```json
{"item":"Выручка","value":"{\"date\":\"20240101\",\"val\":\"12000\"},{\"date\":\"20240401\",\"val\":\"12500\"}",
 "Колонка группы":"Факт","valueItemID":"626","RGcolumnsID":"Факт","Метка":"ТехноСбыт"}
```

Значение связывается со строкой модели **по имени** (`item` = «Строка бюджета» записи
«Значение») и по «Метке», а не ссылкой на строку модели. Отсюда правила:
одинаковое написание имени в «Строке» и «Строке бюджета» обязательно; «Метка» значения
должна совпадать с «Меткой» строки; отчёт отдаёт значения **всех** компаний сразу —
фильтрация по «Метке» происходит в рабочем месте.

## Формулы

Пишутся ссылками на другие строки: `[Выручка]-[Себестоимость]`,
`Math.round([EBITDA]/[Инвестиции]*100)`. Допускается и id-форма (`[648]-[652]`) — при
загрузке `dash.js` приводит имена к id (`dashResolveFormulaNames`, issue #4661): сначала
внутри своей панели, затем по всей модели, если имя единственное. Отдельные формы:

- `[]` — «значение берётся из источника как есть»;
- цельная `[Имя]` или `[Отчёт.Поле]` — ссылка на источник значения, не арифметика (в id не переводится);
- `[-1]`, `[-2]` — смещения по соседним ячейкам, работают при `RGtype=formulas`.

## Словарь периодов

Из `period` рабочее место берёт **имя таблицы-словаря** и читает её целиком:
`object/Квартал?JSON_DATA&LIMIT=10000` (issue #4661: раньше фильтровало сервером через
`FR_С`/`FR_По`, что ломало SQL — см. [queries.md](queries.md)). Строка словаря позиционна:
`r[0]` — заголовок колонки, `r[1]` — С, `r[2]` — По. В диапазон берутся периоды, целиком
лежащие внутри `[С; По]` дэшборда. Нет записей словаря на нужные годы — не будет и колонок.

## Создать модель с нуля (порядок вызовов)

```bash
# 1) справочники (если пусты): Период (481), Квартал/Месяц/Год (482/487/490) — с С и По,
#    Колонка группы (495): «Факт»/«План», Строка бюджета (493), Ед.изм. (478), Тип RG (473)
# 2) дэшборд
POST /{db}/_m_new/559?JSON=1   up=1, t559=ТехноСбыт, t560=01.01.2024, t561=31.12.2025, t562={id «Квартал»}
# 3) лист / панель
POST /{db}/_m_new/551?JSON=1   up={dashId},  t551=P&L, t555={id «Квартал»}
POST /{db}/_m_new/537?JSON=1   up={sheetId}, t537=Финансовые результаты, t543=ТехноСбыт
# 4) группа колонок панели
POST /{db}/_m_new/525?JSON=1   up={panelId}, t525=1, t527={id «Repeating group»}, t534={id «Факт»}
# 5) строки: входные и вычисляемые
POST /{db}/_m_new/509?JSON=1   up={panelId}, t509=Выручка,          t511=1, t524=ТехноСбыт
POST /{db}/_m_new/509?JSON=1   up={panelId}, t509=Валовая прибыль,  t511=1, t524=ТехноСбыт, t515=[Выручка]-[Себестоимость]
# 6) числа (по одной записи на период)
POST /{db}/_m_new/496?JSON=1   up=1, t496=12000, t498=01.01.2024, t500={id «Выручка» в 493}, t506={id «Факт»}, t508=ТехноСбыт
```

Открывать: `/{db}/dash/{dashId}`. Первым делом проверить контракт отчёта:
`report/Дэшборд?JSON_KV&FR_modelID={dashId}` — в ответе должны быть ключи `period`,
`RGtype`, `RGcolumns` (смотреть **наличие ключа**, а не значение).

## Проверка живой модели (что смотреть по порядку)

1. `report/Дэшборд?JSON_KV&FR_modelID={id}` — есть ли `period`, `RGtype`, `RGcolumns`, `Метка`;
2. `object/{период}?JSON_DATA&LIMIT=10000` — есть ли записи словаря на нужные годы (ответ обязан быть массивом, а не текстом ошибки);
3. `report/Дэшборд.ЗначенияЗаПериод?JSON_KV&Fr=…&To=…` — приходят ли `value` и совпадают ли `item`/`Метка` с именами строк;
4. в браузере: `<div class="f-panel" f-period="…">` — значение `undefined` означает, что отчёт не отдал `period`;
5. «🎯 Оптимизация» (кнопка появляется по флагу `opti` в хэше, issue #4659) читает ту же разобранную модель через `window.dashLiveState()` — если отчёт «Модель не загружена», проблема на шагах 1–3, а не в модуле.

## Грабли
- **Симптом:** модель показывает только имена строк — ни одной колонки периода, в отладке `Panel id=fpNNN period=undefined` → **Причина:** отчёт «Дэшборд» не отдаёт `period`/`RGtype`/`RGcolumns`: колонка есть, но без «Имени в отчете» (`t100`) либо с галкой «Скрыть» (`t107`) — в `JSON_KV` такого ключа нет → **Фикс:** проставить `t100`, снять `t107`, недостающие колонки добавить `_m_new/28?up={queryId}` с `t28={reqId}`; для `RGtype` брать «Код» типа RG, а не сам ref. *(08.08.2026, issue #4661, finmo/dash)*
- **Симптом:** колонки периодов есть, а клетки пустые → **Причина:** значения не находятся по имени: «Строка бюджета» записи «Значение» названа иначе, чем «Строка» модели, либо расходятся «Метки» → **Фикс:** сверить `item`/`Метка` из `report/Дэшборд.ЗначенияЗаПериод` с `item`/`Метка` из `report/Дэшборд`; для другого имени источника у строки есть `itemSrcName` (issue #2682). *(08.08.2026, issue #4661)*
- **Симптом:** вычисляемые строки (валовая прибыль, EBITDA, ROI) пусты, входные заполнены → **Причина:** формулы написаны по именам, а ячейки считались только по `[id]` → **Фикс:** обновить `js/dash.js` (перевод имён в id при загрузке) или писать формулы в id-форме. *(08.08.2026, issue #4661)*
- **Симптом:** поля дат в строке фильтра показывают текущий год, а данные в модели — за другой период → **Причина:** строка фильтра инициализировалась текущим годом, тогда как расчёт шёл по «С»/«По» дэшборда → **Фикс:** обновить `js/dash.js`: до первого «Применить» строку фильтра задаёт сам дэшборд. *(08.08.2026, issue #4661)*
- **Симптом:** `object/{период}?…&FR_С=>=…` отвечает `Unknown column 'По' in 'on clause'` → **Причина:** `FR_<имя>` резолвится по имени ТИПА реквизита (`С_т`), не по псевдониму («С») → **Фикс:** словарь читается целиком (`LIMIT=10000`, без `FR_`), диапазон `[С; По]` отбирает `dashFilterPeriodDict` на клиенте; в `object/` фильтровать `F_{reqId}`. Ядро под это не правится (#4672). *(09.08.2026, issue #4672)*
- **Симптом:** одинаковые имена строк в разных панелях, формула считает не то → **Причина:** имя в формуле резолвится сначала внутри своей панели, а если строки с таким именем нет — по всей модели; при двух одноимённых строках в разных панелях ссылка неоднозначна и не переводится → **Фикс:** имена строк в пределах модели держать уникальными либо ссылаться по id. *(08.08.2026, issue #4661)*
- **Симптом:** модель перенесена конвертором `dash-import` (дэшборд, листы, панели, строки и числа на месте), а колонок периода нет; таблица-словарь периода (`/{db}/table/490` «Год» в finmo) пуста → **Причина:** экран конвертора исполнял свою цепочку записи и словарь периода не заполнял вовсе — ядро такую операцию отдавало (`create-period-dict`), исполнителя у неё не было → **Фикс:** словарь заполняется ПЕРВЫМ шагом записи, годы файла плюс запас в три года, у каждой записи проставлены обе границы (`С` = 01.01.ГГГГ, `По` = 31.12.ГГГГ) — без них `dashFilterPeriodDict` строку словаря отбрасывает; нет таблицы словаря или её границ — конвертор останавливается ДО записи модели и называет причину. Что именно ушло в базу, видно в панели отладки конвертора (выгружается JSON-файлом). *(11.08.2026, issue #4718)*
