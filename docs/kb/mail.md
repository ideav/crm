# Почта приложения: SMTP ящика клиента (/_mail)
> Часть базы знаний Integram. Индекс: [docs/kb/README.md](README.md)

## На пальцах (для человека)
Приложение может отправлять письма через **свой SMTP-ящик** (Яндекс, Mail.ru, Gmail
или корпоративный): админ базы один раз вносит настройки, дальше приложение шлёт
письма через эндпоинт `POST /<db>/_mail`. Пароль приложения хранится зашифрованным
ключом сервера и через API не отдаётся. Лимит писем в час на базу защищает от
рассылок и от забора ящика спам-фильтром.

## Справочник (для агента)
### Настройка
Служебная таблица «Почта для отправки» создаётся лениво: первый вызов `/_mail` от
администратора базы (владелец, admin, роль «Администратор») создаёт таблицу с полями
«SMTP-сервер», «Порт» (число, по умолчанию 465), «Логин», «Пароль приложения» (тип
PWD), «От кого», «Лимит в час» (по умолчанию 20) и «Подсказка» (куда идти за паролем
приложения для Яндекса, Mail.ru и Gmail). Грант WRITE на неё выдаётся роли
«Администратор». Редактирование — через обычную карточку записи: `/<db>/edit_obj/<id>`
(адрес и id админ получает в тексте ошибок `/_mail`).

- **Пароль приложения** (не обычный пароль ящика). Яндекс - id.yandex.ru/security -
  Пароли приложений; Mail.ru - Настройки - Пароли для внешних приложений; Gmail -
  только при включённой двухэтапной проверке, myaccount.google.com/apppasswords.
- Шифрование: AES-256-GCM, ключ = HMAC-SHA256("mailpwd:<база>", ADMINHASH.SALT).
  В API (`object`, `edit_obj`, отчёты) значение реквизита типа PWD маскируется
  `******`, при сохранении маска не перезаписывает прежнее значение.
- **Право отправки** = грант READ или WRITE на таблицу «Почта для отправки»
  (без гранта - 403). Владелец базы (логин = имя базы) и admin - без гранта.
- **Лимит** «Лимит в час» на базу; 0 = запрет отправки; не задан = 20. Счёт по
  журналу `logs/<база>_mail.jsonl` за последний час (только успешные).

### Вызов
```
POST /<db>/_mail        Content-Type: multipart/form-data или application/json
Fields: _xsrf, to (адресаты через запятую/точку с запятой/пробел, до 10),
        subject, body, file (загруженный файл) или rec+req (файл из реквизита
        записи: id записи + id реквизита с файлом)
```
Ответ `{"status":"ok","message_id":"<...>","to":N}`. Ошибки - стандартные JSON
`[{"error":...}]` с кодами: 405 (не POST), 403 (xsrf или нет права), 400 (настройки
или параметры), 429 (лимит), 502 (SMTP: недоступен, не принял логин/пароль
приложения, отклонил адресата, не поддерживает STARTTLS).
Результат каждого вызова - в журнале `logs/<база>_mail.jsonl`.

### SMTP-транспорт
- 465 - сразу `ssl://`; 587 - STARTTLS обязателен; прочие порты - STARTTLS если
  сервер его предлагает, иначе отправка только на loopback (127.0.0.1, localhost).
- AUTH LOGIN, MAIL FROM = «От кого», тема и тело в UTF-8 (base64), вложение -
  multipart/mixed (base64), до 10 адресатов, файл до 10 МБ.

## Грабли
- **Симптом:** админ отредактировал запись настроек, пароль приложения «слетел» →
  **Причина:** форма отдаёт маску `******` обратно при сохранении → **Фикс:** маска
  не перезаписывает значение реквизитов типа PWD (#5494, `Skip_hidden_pwd`), менять
  пароль - вписав новый, очистить поле - стирает пароль.
- **Симптом:** `/_mail` отвечает «пароль приложения не читается - внесите заново» →
  **Причина:** значение не расшифровывается (например, пароль был внесён до
  шифрования) → **Фикс:** админ вписывает пароль приложения заново.
- **Симптом:** 502 «сервер не поддерживает STARTTLS» → **Причина:** порт 587 или
  не-loopback без STARTTLS - ядро не шлёт логин/пароль открытым текстом → **Фикс:**
  указать порт 465 (ssl) или сервер с STARTTLS.
- **Симптом:** 429 «лимит» → **Причина:** hourly limit базы исчерпан → **Фикс:**
  подождать или увеличить «Лимит в час» (0 запрещает отправку совсем).
- **Симптом:** 403 «нет права на отправку» → **Причина:** у роли нет гранта READ/WRITE
  на таблицу «Почта для отправки» → **Фикс:** выдать грант через роль.

*(issue #5494)*
