# Журнал базы: `logs/<db>_log.jsonl` и `logs/<db>_sql.jsonl`

## На пальцах

У каждой базы два файла журнала в каталоге `logs/`, по строке JSON на событие:

- `<db>_log.jsonl` — кто, когда и каким запросом обратился к базе;
- `<db>_sql.jsonl` — что поменялось в данных: какая запись, значение до и после.

Строки одного HTTP-запроса связаны общим `rid`, поэтому по нему видно, какие изменения сделал
этот запрос. Если запрос пришёл от ИИ, логин записан с суффиксом `~ai`. Каждую задачу ИИ-чата
можно найти по полю `ai_job`. Пароли, токены и xsrf в журнал не попадают.

## Справочник

Пишет `index.php`: `logRequest()` — строку запроса (при завершении PHP), `Exec_sql()` →
`logChangeBefore()`/`logChangeAfter()` — изменения, `wlog()` — служебные заметки.
Кодировка UTF-8, одна строка — один JSON-объект.

### Строка запроса (`_log.jsonl`)

```json
{"v":1,"ts":"2026-10-08T23:41:05.123+03:00","rid":"k3f9q2","user":"ivanov~ai","uid":512,"role":"manager","ip":"104.128.137.21","m":"POST","path":"/acme/_m_set/5231","params":{"t20":"***","_xsrf":"***","t118":"Закрыта"},"st":200,"ms":84,"sqls":7,"sql_ms":12.4,"ai_job":"a1b2c3"}
```

Служебная заметка (вход, почта, предел времени `[time limit Nc]`, OAuth):
`{"v":1,"ts":…,"rid":…,"user":…,"uid":…,"msg":"…"}`.

### Строки изменений (`_sql.jsonl`)

```json
{"v":1,"ts":"…","rid":"k3f9q2","user":"ivanov~ai","uid":512,"op":"update","id":5240,"up":5231,"t":20,"old":"В работе","new":"Закрыта","ms":0.8}
{"v":1,"ts":"…","rid":"k3f9q2","user":"ivanov~ai","uid":512,"op":"insert","id":5301,"up":5231,"t":118,"new":"Позиция 3","ms":0.4}
{"v":1,"ts":"…","rid":"k3f9q2","user":"ivanov~ai","uid":512,"op":"delete","id":5288,"up":5231,"t":118,"old":"Позиция 1","ms":0.6}
{"v":1,"ts":"…","rid":"p7x0aa","user":"petrov","uid":77,"op":"import","kind":"csv","table":18,"file":"deals.csv","inserted":1200,"updated":35,"deleted":0,"errors":2,"ms":5321}
{"v":1,"ts":"…","rid":"q1w2e3","user":"admin","uid":0,"op":"sql","sql":"UPDATE acme SET id=… WHERE …='***'","n":1,"ms":0.3}
```

| Поле | Значение |
|---|---|
| `v` | версия формата, 1 |
| `ts` | ISO 8601 с миллисекундами и поясом сервера |
| `rid` | id запроса (6–8 символов), общий для строки запроса и всех его изменений |
| `user` | логин; запрос с `client=ai` — с суффиксом `~ai` (`aiLogUser()`) |
| `uid` | id пользователя |
| `role` | роль (только `_log`) |
| `ai_job` | параметр запроса `ai_job` — id задачи ИИ-чата (в обоих файлах) |
| `op` | `insert` / `update` / `delete` / `import` / `ddl` / `sql` |
| `id`, `up`, `t` | строка ядра: id, родитель, тип (у `update` — после изменения) |
| `old`, `new` | значение до и после; у `update` есть оба, у `delete` — `old`, у `insert` — `new` |
| `old_up`, `old_t`, `old_ord`, `ord` | у `update` — только если изменились родитель, тип, порядок |
| `old_len`, `new_len` | полная длина значения, если оно длиннее 2 КБ и обрезано |
| `sql`, `n` | у `op:"sql"`/`"ddl"`: текст SQL со скрытыми строковыми литералами и число затронутых строк |
| `err` | текст ошибки, если изменение не прошло |
| `ms` | время выполнения SQL (у `import` — всего импорта) |

### Правила

- **Секреты.** Значения строк типов PASSWORD (20), XSRF (40), TOKEN (125), SECRET (130) — `"***"`.
  В параметрах запроса скрыты `pwd`, `password`, `token`, `secret`, `reset`, `regpwd*`, `c`, `s`,
  `code`, `_xsrf`, `t20`/`t40`/`t125`/`t130` и всё, что ловит `maskSensitiveLogValue()`.
  В `op:"sql"` скрыты все строковые литералы.
- **`old`** читается до изменения: `SELECT id, up, ord, t, val FROM <db> WHERE <условие изменения>`.
  Удаление поддерева (`Delete()`) даёт строку `delete` на каждую удалённую строку.
- Изменение, которое не распознано по шаблону (`UPDATE <db> SET … WHERE …`, `DELETE FROM <db> WHERE …`,
  `INSERT INTO <db> (up, ord, t, val) VALUES …`, `INSERT INTO <db> (id, up, ord, t, val) VALUES (N, …)`),
  меняет сам `id` или задевает больше 1000 строк, пишется одной строкой `op:"sql"`.
- **Импорт** (`import=1`, `kind`: `csv` — файл `DATA`, `bki` — с метаданными, `json` — JSON-архив):
  больше 16 изменений — одна строка `op:"import"` со счётчиками, до 16 включительно — построчно.
  Прерванный импорт даёт сводку с `"err":"interrupted"`. `_m_batch` — не импорт, пишется построчно.
- `SELECT` в `_sql.jsonl` не пишется.
- **Ротация** по размеру: `LOG_ROTATE_MB` (по умолчанию 50, задаётся в `include/connection.php`).
  Файл уходит в `<db>_sql.N.jsonl`, где N — следующий свободный номер: больший N — более свежий
  архив, номера существующих архивов не меняются.
- Запись — `fopen(…, "a")` + `flock(LOCK_EX)`, одна `fwrite` на строку.

## Грабли

- **Строки запроса нет при `exit` в обработчике завершения.** Обработчик фатальных ошибок в начале
  `index.php` завершается `exit`, а после `exit` другие функции `register_shutdown_function` не
  вызываются. Поэтому этот обработчик сам вызывает `logRequest()` перед `exit`. Новый `exit` в
  обработчике завершения → сначала `logRequest()`.
- **`die("…")` в PHP-мерке выходит с кодом 0.** Отказ в мерке журнала (`experiments/jsonl-log-5104.test.php`)
  — только `fwrite(STDERR, …); exit(1);`.
