# Дэшборд / финмодель: устройство кода и развитие (`dash.js`)
> Часть базы знаний Integram. Индекс: [docs/kb/README.md](README.md)
> Модель данных (таблицы, отчёты, порядок создания модели) — соседний док
> [dashboard.md](dashboard.md); здесь описан **код** рабочего места и как его развивать.

## На пальцах (для человека)

Рабочее место «Дэшборд» (`/{db}/dash/{id}`) — это одна HTML-страница-оболочка и один
большой JS-движок. Движок читает из базы два отчёта (структура модели и числа),
сам рисует листы-вкладки, панели и таблицы, считает формулы прямо в браузере и пишет
изменения ячеек обратно в базу стандартными вызовами `_m_*`. Серверной части у рабочего
места нет: всё, что видит пользователь, сделано в `js/dash.js` поверх обычного API Интеграма.

Три слоя модели — Дэшборд → Лист → Панель → Строка — рисуются тремя вложенными
шаблонами-строками; колонки каждой панели добавляет описание RG (тип RG задаёт режим:
повтор по периодам, «Факт/План», формула по соседним ячейкам, сумма, единицы, свой отчёт).
Числа лежат в отдельной таблице «Значение» и находятся по имени строки, колонке группы
и «Метке». Там, где строке назначен отчёт или панель питается своим `panelQuery`,
ячейки рисуются только для чтения.

Вокруг ядра живут: визуализация панелей (таблица/графики Chart.js/сводная PivotTable.js
с сохраняемыми настройками), локальные фильтры панелей, режим плитки, оптимизация модели
(кнопка «🎯 Оптимизация», граф зависимостей, goal-seek, аномалии, диагностика) и конвертор
переноса модели из Excel (`dash-import`).

## Конвейер загрузки (что зовёт что)

1. **Boot**: хвост `dash.js` (строка 7420) разбирает путь `/dash/{id}` и зовёт `dashLoad(id)`
   (6269) → `dashReset()` (6194) чистит состояние и DOM → `get_record/{id}`.
2. **`dashGetRecord`** (2458): проверяет `type === 'Дэшборд'`, ставит заголовок, зовёт
   `report/Дэшборд?JSON_KV&FR_modelID={id}&period={детализация}`.
3. **`dashGetModel`** (2475) — центральная функция. По одной строке отчёта на строку модели:
   - строит DOM из шаблонных строк `sheetTabTpl`/`sheetTpl`/`panelTpl`/`itemTpl` (56–88):
     вкладка листа → лист с фильтр-баром → панель с шапкой → строка-`<tr>` с именем и
     ссылкой правки (`/{db}/table/997?F_U={панель}&F_I={строка}`);
   - собирает состояние: `dashItems` (id строки → имя/формат/ед.изм./Метка),
     `dashModelData[panelKey]` (панель: `items`, `rgs`, `settings`, `panelFilters`,
     `panelQueryParts`), `dashFormulas[id]`, `dashValues`;
   - параллельно запускает: `report/Дэшборд.ЗначенияЗаПериод` → `dashGetSrc` (2287),
     словари периодов `object/{Год|Квартал|Месяц|Неделя}?JSON_DATA&LIMIT=10000` →
     `dashGetPeriodDict` (2204), отчёты viz-настроек (`dashGetVizReport`), данные панелей
     с `panelQuery` (`dashGetPanelValues` 2339), отчёты row-формул (`dashGetRep`);
   - row-формула, чей `[Отчёт.Поле]` совпал с `panelQuery` своей или чужой панели, не
     делает отдельный запрос, а встаёт в очередь `dashPendingPanelRows` (issue 2718/2727);
   - в конце — `dashResolveFormulaNames` (1530): имена в формулах переводятся в id строк
     (сначала внутри своей панели, затем по модели, однозначные только).
4. **Счётчик `dashAjaxes`**: каждый ответ его уменьшает и зовёт `dashDrawPeriods` (1800);
   когда всё дошло (`dashAjaxes === 0`) — отрисовка:
   - колонки по типам RG: `rg` (периоды × подколонки «Факт/План»), `value`, `formulas`
     (`data-rg-formula`, смещения `[-1]`/`[+1]`), `mu`, `line`, иначе — колонки из отчёта
     RG → Запрос, при матричном источнике с `data-matrix-*` атрибутами;
   - каждой ячейке выставляется `ready` (`1` — значение есть, `0` — ждём расчёта);
   - затем `dashGetRepVals` (1745, значения из отчётов), `dashCalcCells` (1586),
     `dashCalcRGFormulas` (1656), применение viz-настроек и локальных фильтров, `dashDebug` (2121).

Состояние в замыкании; наружу — `window.dashGetModel`, `window.dashApplyFilter` (6226,
частичная перезагрузка активного листа), `window.dashLiveState` (6214, снимок
`items/formulas/values/periods` для оптимизатора), отладочный `?DEBUG=1` → `dashTrace`.

## Контракт ячейки (data-* атрибуты)

Ячейка — `<td class="f-cell">` из `cellTpl` (89). По атрибутам её находит и правка, и формулы:

| Атрибут | Значение |
|---|---|
| `data-src` | источник ячейки: `rg`/`value` — таблица «Значение» (редактируемая); `matrix` — матричный источник (редактируемая); `rg-formula`/`value-formula` — формула строки (модалка формулы); `report`/`mu`/`linesum`/`rgformula` — только чтение |
| `range` | `YYYYMMDD-YYYYMMDD` периода колонки или `-` |
| `data-rg-col` | имя подколонки («Факт», «План») или подпись периода |
| `data-dash-label` | «Метка» строки для фильтра значений |
| `data-value-item-id` | id записи «Значения», найденной при загрузке |
| `data-formula` / `data-rg-formula` | текст формулы строки / RG-формулы |
| `ready` | `0` — формула ещё не посчитана |

Клик по ячейке — один делегированный обработчик на `#dash-model` (6848): редактируемые
`src` открывают инлайн-правку, формульные — модалку формулы, остальные показывают
подсказку «Только чтение». Рядом — прямоугольное выделение ячеек мышью с бейджем
Σ/N/⌀ и копированием TSV (IIFE с 6888, issue 2653/2681).

## Формулы

- Регулярки форм: `repRegex` `[Отчёт.Поле.Группа]`, `itemRegex` `[Имя строки]`,
  `itemIdRegex` `[123]`, `exprRegex` `СУММА([А]:[Б])` (js/dash.js:3–6).
- Формула строки хранится в `dashFormulas[id]`; `dashCellSrc` (26) по её форме решает,
  чем питается ячейка: `[]` — источник как есть; `[Отчёт.Поле]` — отчёт; остальное —
  арифметика (`{src}-formula`).
- **Расчёт — итерации до неподвижной точки**: `dashCalcCells` гоняет по `td[ready="0"]`,
  подставляя вместо `[id]` значения ячеек-зависимостей с тем же `range` и той же
  `data-rg-col` (подколонки «Факт/План» не смешивать — issue 2652), затем `eval()`.
  Не посчитанное за 100 итераций помечается `dash-err`; пустые операнды дают пустую
  ячейку, а не N/A (issue 2660). Поиск ячейки-зависимости — `getElementById`, id могут
  начинаться с цифры (issue 2074).
- RG-формулы (`RGtype=formulas`) считают по ячейкам своей строки: `[ИмяКолонки]` или
  смещения со знаком `[-1]`/`[+1]`; число без знака — не адрес, а имя колонки (issues 4646/4648).
- Правка формулы с листа: `dashShowFormulaModal` (6714) → `_m_save/{id строки}` с
  `formula=` и `_xsrf` → `dashFormulaSaveDone` (6740) обновляет `dashFormulas` и
  пересчитывает `dashCalcCells` + `dashCalcRGFormulas`.

## Куда рабочее место пишет (id таблиц зашиты в коде)

Правки идут стандартным API `_m_new`/`_m_save`/`_m_set`/`_m_del`, но **id таблиц и
реквизитов зашиты в константах и URL** — в базах с другой схемой правка ячеек не работает:

| Что | id | Где |
|---|---|---|
| Значение (таблица) | 1010 | `dashValueSearchUrl` (6529), `dashValueSearchDone` (6567) |
| Дата / «Строка бюджета» / «Шапка RG» / «Метка» значения | 1039 / 1042 / 1104 / 155556 | там же + константы (8–10) |
| Матричный источник (таблица и поля) | 155551 + поля 155552–155554, 155556–155557 | константы (8–10), `dashMatrixUpsertCache` (6346), `_m_new/155551` (6468) |
| Строка (ссылка правки строки) | 997 | `itemTpl` (83) |
| Настройки панели (JSON viz) | реквизит `t1165` панели | сохранение модалки отображения: `_m_set/{panelID}` (5715) |

Поиск записи значения перед записью: `object/1010?JSON_OBJ&FR_1039={дата}&FR_1042={строка}
&F_1104={группа}&F_155556=%` — дальше по числу найденного: создать (`_m_new/1010?up=1`),
править (`_m_save`), удалить (`_m_del`) или показать модалку «найдено несколько значений».

## Визуализация и настройки панелей

- Типы — `DASH_VIZ_TYPES` (2699): таблица, линейный/круговой/столбчатый график, сводная.
  Chart.js и PivotTable.js подгружаются с CDN лениво и один раз (`dashEnsureChartJs` 3019,
  `dashEnsurePivotJs` 3049); рендер откладывается, пока панель скрыта вкладкой.
- Настройки панели (тип, маппинг полей, выбранная строка, размер, общие настройки осей,
  кастомные опции Chart.js) собираются модалкой «Варианты отображения» в JSON и пишутся
  в реквизит «Настройки» панели (`_m_set/{panelID}` с `t1165`, js/dash.js:5715); на
  загрузке применяются `dashPanelApplySettings` (5026).
  Кастомные опции ограничены 8000 символами, док — [CHART_CUSTOM_OPTIONS.md](../CHART_CUSTOM_OPTIONS.md).
- Размеры графиков/таблиц и режим плитки листа хранятся в cookies (имя = id панели);
  сброс — иконкой на листе (`dashResetSheetSizeCookies` 4098).
- Локальный фильтр панели (`dash-panel-filter-modal`, 5753+) фильтрует строки и ячейки
  уже загруженных данных; серверная часть фильтра уходит в URL отчёта (`panelFilter`).

## Оптимизация модели (`js/dash-optimize.js`)

Кнопка «🎯 Оптимизация» и модалка появляются только по флагу `opti` в хэше адреса
(`/#opti`, рядом с `tab=...`; без флага разметка удаляется из DOM — issue 4659).
Модель берётся геттером `window.dashLiveState()` — `dash.js` держит её в замыкании, и
снимок устарел бы после `dashReset` (issue 4661). Отчёт: D1 граф зависимостей строк
(классификация вход/вычисляемая/KPI по эвристике имени), A — goal-seek «поднять KPI на
N%» с чувствительностями рычагов и Ньютоном, B — аномалии (робастный z по ряду, дрейф
Себестоимость/Выручка), C — факторная диагностика просевшего показателя. В БД не пишет.

## Конвертор Excel → модель (`dash-import`)

Пайплайн: файл → `recognizeModel(grids)` (форма книги → структура модели + журнал
непереносимого) → **предпросмотр** (в базу ничего не пишется, пока оператор не увидел
распознанное) → `buildCreateOps` (операции `_m_new` с переиспользованием существующих
записей; словари модели — «Период», «Год», «Тип RG», «Строка бюджета» — проверяются и
дозаполняются до записи, issue 4718) → запись пулом до 5 потоков (`js/integram-batch.js`,
issue 4716) → панель отладки с выгрузкой JSON-трассы. Ядро чистое (без DOM и сети) —
покрывается headless-тестами на реальных образцах из тикетов.

## Инструкция для развития

### Общие правила (проверяются гейтом)

1. **Сначала падающий тест, потом код**; поведение — не текст исходника (правила гейта в
   [CLAUDE.md](../../CLAUDE.md)). Образцы: `experiments/dash-period-dict-4661.test.js`
   (словарь периодов), `experiments/dash-optimize-gate-4659.test.js` (гейт флага на
   подставном DOM), `experiments/dash-import-*.test.js` (ядро конвертора на реальных книгах).
2. **Ядро `dash.js` не трогаем без нужды** — рабочий инвариант `experiments/dash-core-untouched-4672.test.js`
   (issue 4672): правки чтения словарей делаются на клиенте движка, ядро платформы не правится.
3. Правилo правки `js/css` — поднять версионный суффикс `?{_global_.version}.N` во всех
   шаблонах, где файл подключён (сторож #4722).
4. Модалки — существующие заготовки `dash.html` или по образцу (класс `open`, Escape,
   клик по фону); `alert`/`confirm`/`prompt` запрещены (гайд, раздел 8).
5. Новое состояние — в переменные замыкания рядом с `dashModelData` (91–102) и в
   `dashReset` (6194) — иначе следующая модель унаследует чужие данные.
6. Наружу выставлять только точечными `window.dash*` назначениями (6207–6224); для
   тяжёлой логики без DOM — отдельный модуль с чистыми функциями и `module.exports`
   (образцы: `dash-optimize.js`, `dash-import.js`).

### Развитие №1: создание листов, панелей, строк и RG прямо на листе

Сейчас структура редактируется в таблицах (ссылка правки в строке — `itemTpl`) и
собирается конвертором; на самом листе создаётся ничего. План:

- **Права**: кнопки создания показывать только админу — флаг уже есть, `dashIsAdmin`
  (`js/dash.js:57`), им же гейтятся иконки настроек.
- **Запись**: цепочка `_m_new` по контракту [dashboard.md](dashboard.md) («Создать модель
  с нуля»): Дэшборд → Лист (`up={dashId}`) → Панель (`up={лист}`) → Строка и RG
  (`up={панель}`); id таблиц брать из `metadata` (см. «Куда рабочее место пишет» —
  зашитые константы правки ячеек на схему не влияют, создание идёт по текущей базе).
- **UI**: точки входа — кнопка «+ лист» рядом с `.sheet-tabs` и иконка «+ панель/строка»
  в `.f-panel-header` (шаблоны `sheetTpl`/`panelTpl`, 56–75); ввод имени — мини-модалка
  по образцу формульной.
- **Обновление экрана**: после записи не перестраивать всё руками — вызвать
  `dashApplyFilter(sheetEl)` (6226, частичная перезагрузка листа через отчёт) или
  `dashLoad(dashRecordId)` (6269, весь дэшборд): отчёт «Дэшборд» сам отдаст новые записи.
- **Тесты**: разбор пути «создать → перечитать» на подставном DOM по образцу
  `dash-optimize-gate-4659.test.js`.

### Развитие №2: подсветка влияющих ячеек при наведении

Все данные для этого уже в DOM и в состоянии:

- **Прецеденты** выделенной ячейки — ссылки `[id]` формулы её строки
  (`dashFormulas[rowId]`, регулярка `itemIdRegex`), а для RG-формул — соседние ячейки
  той же строки по смещению. Поиск целевых ячеек — тот же селектор, что в `dashCalcCells`
  (1606–1622): `#id .f-rg-cell[range="..."]`/`.f-col-cell[range="..."]`, при `range="-"`
  — любой, затем фильтр по `data-rg-col`.
- **Зависимые** (обратное направление) — построить одноразовый индекс
  `id строки → [id строк, чья формула на неё ссылается]` из `dashFormulas` при
  `dashResolveFormulaNames` (1530), цель — те же `td` по `data-item-id` + `range`.
- **Показ**: делегированные `mouseover`/`mouseout` на `#dash-model` (образец —
  `dashShowReadonlyTip` 6837), классы в `css/dash.css` по образцу `dash-cell-selected`;
  курсор уже над ячейкой — её саму не подсвечивать дважды.
- **Границы**: ячейки `data-src="report"` и панели `f-panel-readonly` влияний не имеют;
  у строки с `[]`-формулой прецедентов нет.
- **Тесты**: построение индекса и селектор — headless на подставном DOM (перечень
  найденных ячеек для известной модели).

### Развитие №3: редактирование формул на листе

База уже есть: клик по вычисляемой ячейке (`rg-formula`/`value-formula`, 6875) открывает
модалку `dashShowFormulaModal` (6714), сохранение — `_m_save/{id строки}` с `formula=`,
пересчёт после сохранения — `dashFormulaSaveDone` (6740). Доработка:

- **Вход с любой строки**, а не только с вычисляемой ячейки: иконка «fx» в `.f-item`
  (шаблон `itemTpl`, 83) или в контекстном меню строки; для входной строки модалка
  стартует пустой формулой, сохранение превращает её в вычисляемую.
- **RG-формулы**: сейчас `data-rg-formula` правится только в таблицах RG — добавить
  правку `RG → Формула` (`_m_set/{id RG}`) из модалки с подсказкой про знаковые смещения
  `[-1]`/`[+1]` (issues 4646/4648).
- **Подсказка имён**: при вводе показывать имена строк панели (источник — `dashItems`);
  сохранять можно имена — их в id переведёт `dashResolveFormulaNames` (1530) при
  следующей загрузке, а ссылку на чужую панель писать по id (однозначность имён —
  issue 4661).
- **Тесты**: пересчёт после правки формулы на подставном DOM (образец — проверки
  `dashCalcCells` в `experiments/atex-dashboards.test.js` и тестах тикета 4661).

## Грабли

- **Симптом:** модель рисуется, правка ячейки «Сохранено», а в базе ничего → **Причина:**
  id в `dashValueSearchUrl`/`_m_new/1010` зашиты под одну схему базы; в другой базе
  таблица с таким id другая → **Фикс:** сверить id с `metadata` базы и править константы
  (8–10) и URL поиска/записи. *(проверяемо: `js/dash.js:6529–6590`)*
- **Симптом:** формула в `title` ячейки показывает `(Not found 123)` → **Причина:** в
  `dashReplaceItems` (1564) нет строки с таким id — строку удалили, формула осталась →
  **Фикс:** поправить формулу строки; подсказка «влияющих ячеек» (развитие №2) ловит это
  до пересчёта.
- **Симптом:** `eval` формулы падает в консоль, ячейка пустая → **Причина:** пустые
  операнды дают невалидный JS; так и задумано — «нет данных», а не «сломано» (issue 2660) →
  **Фикс:** править не движок, а данные/формулу.
- **Симптом:** в колонке «Факт» появились числа «Плана» → **Причина:** подстановка
  `[id]` брала первую ячейку с тем же `range`, не глядя на подколонку (issue 2652) →
  **Фикс:** не убирать фильтр по `data-rg-col` в `dashCalcCells` (1617–1622).
- **Симптом:** вкладки/иконки оптимизации видны тем, кому не положено → **Причина:**
  новые элементы вставлены вне проверки `dashIsAdmin` (`js/dash.js:57`) → **Фикс:**
  гейтить admin-only UI этим флагом, как это делают `sheetTpl`/`panelTpl`.
- **Симптом:** правка `js/dash.css` не дошла до пользователя → **Причина:** кэш браузера —
  версионный суффикс в шаблоне не поднят (сторож #4722) → **Фикс:** поднять `N` в
  `?{_global_.version}.N` во всех шаблонах, где файл подключён.
