# Web-socket: живые таблицы, уведомления, события для внешних систем

## На пальцах

Открытая таблица обновляется сама, когда её записи меняет другой пользователь, триггер или
внешняя система. Пользователю можно послать уведомление: оно всплывает на любой открытой
странице базы. Внешняя система подписывается на изменения таблицы и не опрашивает API по таймеру.

Соединения держит отдельный демон `ws-server/` (Node, без зависимостей), потому что PHP-ядро
постоянных соединений не держит. Ядро после каждого запроса с записью сообщает демону, какие строки
изменились. Значения в событие не попадают, только адрес строки. Клиент по событию перечитывает
данные обычным API, и на этом чтении работают все права и маски.

```
браузер / внешний клиент ──ws──► nginx /ws ──► ws-server :8790 ──► GET /<база>/ws_auth?JSON (ядро)
index.php ── POST /push (HMAC) ──► ws-server ──► подписчикам таблицы
```

## Справочник

### Ядро (`include/ws_push.php`, `index.php`)

- `logChange()` (журнал изменений) отдаёт каждую записанную строку в `Ws_collect()`.
  Строки авторизации (TOKEN, XSRF, ACTIVITY, PASSWORD, SECRET) пропускаются.
- После ответа `Ws_flush()` (shutdown) строит события и отправляет их одним POST на `WS_PUSH_URL`.
  Подпись лежит в заголовке `X-Ws-Signature` = HMAC-SHA256(тело, `WS_SECRET`).
  Таймаут 500 мс: если демон лежит, запрос пользователя его не ждёт.
- Событие данных: `{"k":"change","op":"insert|update|delete","id","up","t","types":[…]}`.
  `types` — цепочка типов: тип строки, тип её объекта, тип родителя и так далее до объекта первого
  уровня (`up=1`). При переносе в цепочку входит и старое место.
- Правка метаданных (тип `up=0` или определение его реквизита) даёт `{"k":"schema","t":<тип>}`.
- Сырой SQL, DDL, сводка импорта или больше `WS_MAX_CHANGES` (500) строк за запрос дают
  `"bulk":true`, то есть «перечитать всё».
- Транзакция запроса (InTransaction): откат или выход без COMMIT — её изменения не рассылаются.
- `GET /<база>/ws_auth?JSON[&t=<тип>]` возвращает `{user,user_id,role[,t,read]}`. Через него демон
  проверяет вход клиента и право подписки. Право подписки (`Ws_type_readable`): явное право на тип
  или на его строку-массив; иначе подчинённая таблица наследует право родителя, а таблица первого
  уровня проверяется по `Grant_1level`.
- `POST /<база>/_m_notify` (`_xsrf`): `to` — логины через запятую (до 50), `msg` — текст (до 2000),
  `link` — `/…` или `http(s)://…`. Гостю запрещено. Из PHP: `Ws_notify($логины, $data)`.

Настройки (`include/connection.php`, переменные окружения):

| Константа | Переменная | Пример |
|---|---|---|
| `WS_PUSH_URL` | `INTEGRAM_WS_PUSH_URL` | `http://127.0.0.1:8790/push` |
| `WS_SECRET` | `INTEGRAM_WS_SECRET` | длинная случайная строка, та же у демона |
| `WS_PUBLIC_URL` | `INTEGRAM_WS_PUBLIC_URL` | `/ws` (тот же хост) или `wss://host/ws` |

Пустой `WS_PUSH_URL` или `WS_SECRET` — ядро ничего не копит и не отправляет. Пустой
`WS_PUBLIC_URL` — браузер не подключается.

### Демон (`ws-server/server.js`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `WS_CORE_URL` | — (обязательна) | адрес ядра для `ws_auth`, например `https://ideav.ru` |
| `WS_SECRET` | — (обязательна) | равна `INTEGRAM_WS_SECRET` ядра |
| `WS_PORT` / `WS_HOST` | `8790` / `127.0.0.1` | где слушать |
| `WS_ALLOWED_ORIGINS` | пусто | сайты через запятую, с которых браузер может подключаться, кроме своего хоста |
| `WS_REAUTH_SEC` | `300` | как часто перепроверять вход и права подписок |

- Подключение: `GET /ws?db=<база>` с `Upgrade: websocket`. Вход — куки `idb_<база>` (ядру
  уходит только он) или заголовок `X-Authorization` / `Authorization`. Токен в строке адреса не
  принимается: он попал бы в журналы.
- Подключение со страницы чужого сайта (`Origin` не свой и не из `WS_ALLOWED_ORIGINS`) получает
  403. Иначе чужой сайт подключился бы с куки пользователя.
- Сообщения клиента: `{"op":"sub","t":500}`, `{"op":"unsub","t":500}`, `{"op":"ping"}`.
- Сообщения демона:
  - `{"op":"hello","db","user"}`, `{"op":"sub","t","ok"}`;
  - `{"op":"events","by","reload","events":[…]}` — только события, в цепочке которых есть тип
    подписки;
  - `{"op":"notify","from","data"}`;
  - `{"op":"unsub","t","revoked":true}` — право снято.
- Вход отозван — закрытие с кодом `4401`, переподключаться бесполезно.
- `GET /health` → `{"clients":N}`.

### Браузер (`js/ws-client.js`, компонент таблиц)

- `main.html` задаёт `wsUrl = '{_global_.ws}'` и подключает `js/ws-client.js`.
- `IntegramWS.subscribe(typeId, fn)` возвращает функцию отписки. `fn` получает
  `{by, reload, events}`.
- `IntegramWS.onNotify(fn)`. По умолчанию уведомление показывается через `showToast`.
- После обрыва клиент переподключается с паузой 1 → 30 с, повторяет подписки и передаёт
  подписчикам `reload:true`: события за время обрыва потеряны.
- `integram-table` подписывается на свой тип после первой загрузки (`liveAttach`):
  - пачку чужих событий перечитывает одним `reload()` через секунду;
  - правку схемы — через `refreshData()`;
  - пока ячейка в правке или новая строка не сохранена, ждёт;
  - свои правки в активной вкладке не перечитывает;
  - отключается опцией `live: false`.

### Внешний клиент

```js
const WebSocket = require('ws');   // npm-пакет ws: встроенный WebSocket заголовков не передаёт
const ws = new WebSocket('wss://ideav.ru/ws?db=acme', { headers: { 'X-Authorization': TOKEN } });
ws.onmessage = (e) => console.log(JSON.parse(e.data));
ws.onopen = () => ws.send(JSON.stringify({ op: 'sub', t: 500 }));
```

Встроенный `WebSocket` Node и браузера заголовков не передаёт. Внешнему клиенту с токеном нужен
клиент с заголовками, например пакет `ws`.

### Выкладка

1. Демон — systemd-юнит:

   ```ini
   [Service]
   WorkingDirectory=/var/www/crm/ws-server
   ExecStart=/usr/bin/node server.js
   Environment=WS_CORE_URL=https://ideav.ru WS_SECRET=… WS_PORT=8790
   Restart=always
   User=www-data
   ```

2. nginx в server-блоке сайта:

   ```nginx
   location = /ws {
       proxy_pass http://127.0.0.1:8790;
       proxy_http_version 1.1;
       proxy_set_header Upgrade $http_upgrade;
       proxy_set_header Connection "upgrade";
       proxy_set_header Host $host;
       proxy_read_timeout 3600s;
   }
   ```

3. Ядру — `INTEGRAM_WS_PUSH_URL`, `INTEGRAM_WS_SECRET`, `INTEGRAM_WS_PUBLIC_URL=/ws`
   (окружение php-fpm или `include/connection.php` сервера).

Проверка: `curl -s 127.0.0.1:8790/health`, затем открыть таблицу в двух браузерах и изменить
запись в одном.

## Грабли

- Симптом: браузер получает 403 при подключении, хотя сайт свой. Причина: nginx не передаёт
  `Host`, и демон сравнивает `Origin` с `127.0.0.1:8790`. Фикс: `proxy_set_header Host $host` или
  сайт в `WS_ALLOWED_ORIGINS` (#5269).
- Симптом: события не приходят, а в журнале ядра пусто. Причина: не задан один из
  `INTEGRAM_WS_PUSH_URL` / `INTEGRAM_WS_SECRET`, или секрет ядра не равен `WS_SECRET` демона
  (на `/push` демон отвечает 401). Фикс: одинаковый секрет по обе стороны (#5269).
