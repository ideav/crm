Нагрузочные замеры: выборки, отчёты, потоки

Сервер: 2 vCPU AMD EPYC, 1.9 ГБ RAM, MySQL 8.0.46, PHP 8.3.6. 8 таблиц от 1 тыс. до 1 млн строк (12 и 45 реквизитов), выборки и отчёты-агрегаты по 1, 3 и 5 таблицам. Сырые данные и скрипты — docs/hlt-stand/ в ideav/crm. Калькулятор по этим замерам — sizing.html.

  • в порог 60 с укладываются отчёты по таблицам до 100 тыс. строк; по миллиону строк отчёт идёт дольше минуты — для интерактива он не годится;
  • фильтр отчёта, попадающий в индекс, сначала выбирает строки среза и только их джойнит и агрегирует: за неделю (2.8 тыс. строк из 1 млн) — 586 мс, за год (146.4 тыс. строк) — 16 с, против 130 с по всей таблице. Время отчёта задаёт срез (≈108–146 мкс на строку среза за год), размер таблицы на него не влияет;
  • отчёт по большой таблице проектируется вместе с фильтром — как в любой реляционной СУБД. Фильтр, который в индекс не попадает, заставляет читать всю таблицу при любом срезе: тот же отчёт с числовым диапазоном по коду (ядро сравнивает CAST(val AS FLOAT)) на 1 тыс. строк идёт 60 с, фильтр на одну дату («от» = «до») ядро сейчас сравнивает числом — 34 с на 400 строк (#5469). Кто не позаботился о фильтре на больших объёмах, получит полный проход таблицы на каждый запрос.
