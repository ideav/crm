# Партнёрский раздел личного кабинета (база my)

Раздел «Партнёрская программа» в ЛК (`templates/my/main.html`, секция `section-referrals`) состоит из вкладок: «О программе», «Материалы и ссылки», «Клиенты», «Обучение», «Правила», «Статистика». Новые вкладки показывают материалы с персональными ссылками, клиентов на сопровождении, статус экзамена и активность партнёра.

## Как работает
1. `templates/my/cabdata.html` отдаёт данные партнёра в ответе `/my/cabdata?JSON` — блоки `partnerLinks`, `partnerClients`, `partnerExam`, `partnerStats`. Каждый блок — отчёт Интеграма с тем же именем; столбцы отчёта названы точками вставки.
2. `js/my-mode.js`: `MyMode.loadPartnerData(base)` читает тот же ответ, что и `loadCabData` (один запрос на оба вызова), и разбирает его функцией `readPartnerData`.
3. `js/partner-cabinet.js`: `PartnerCabinet.viewModel` строит модель вида, `PartnerCabinet.render` рисует её через `textContent`, `PartnerCabinet.init` вызывается из `js/cabinet.js` после загрузки данных пользователя.
4. Если отчётов нет, вкладки показывают пустые состояния, а ссылка на страницу услуги с `?aff=<номер партнёра>` остаётся.

## Контракт отчётов
Каждый отчёт фильтруется по текущему пользователю (колонка «Пользователь» с `t104=abn_ID`, `t102=[USER_ID]`, `t107=1`; см. `docs/kb/report-building.md`) и называется точно так, как блок.

| Отчёт (блок) | Столбцы | Содержимое |
|---|---|---|
| `partnerLinks` | `Material`, `Title`, `Token`, `Kind` | по строке на материал партнёра. `Kind`: `video`, `page`, `file`, `bot`, `service`. `Token` — 16–64 знака `A-Z a-z 0-9 _ -` |
| `partnerClients` | `Client`, `Came`, `Did`, `Start`, `Paid` | клиент, дата прихода (дд.мм.гггг), что сделал, начало сопровождения, `1` если оплатил |
| `partnerExam` | `Passed`, `Score`, `ExamDate`, `AttemptsLeft`, `Threshold` | одна строка: `1` если сдан, балл, дата, осталось попыток, порог (80) |
| `partnerStats` | `Clients`, `OnSupport`, `PaidClients`, `Earned`, `Opens`, `People`, `VideoPeople`, `PresentationPeople`, `KpPeople`, `BotStarts`, `Flows` | одна строка итогов за 30 дней |

Адреса ссылок строит кабинет: материал — `https://ideav.ru/m/<Token>`, бот — `https://t.me/Integrammbot?start=<Token>`, услуга — `https://ideav.ru/excel-to-app.html?aff=<номер партнёра>`. Токен другой формы ссылку не даёт.

## Таблицы в базе my (создаёт администратор)
- **Ссылка партнёра:** Пользователь (ссылка), Материал (код), Название, Токен (уникальный), Вид.
- **Событие партнёра:** Пользователь, Тип (`material_open`, `bot_start`, `flow_done` и др.), Материал, Время, Посетитель, Бот (0/1).
- **Клиент партнёра:** Пользователь (партнёр), Клиент, Пришёл, Начало сопровождения, Что сделал, Оплатил (0/1), Прямых обращений.
- **Экзамен партнёра:** Пользователь, Сдан (0/1), Балл, Дата, Осталось попыток.
- Отчёты из контракта собираются по этим таблицам. События из `events.jsonl` скрипта `/m/<токен>` (репозиторий backlogram) переносятся в «Событие партнёра».

## Внедрение на боевой ЛК
1. Слить ветку `partner-cabinet` в `main`, выложить `templates/my/main.html`, `templates/my/cabdata.html`, `js/my-mode.js`, `js/partner-cabinet.js`, `js/cabinet.js`, `css/my-cabinet.css` обычным путём выкладки (новые версии файлов подхватываются через `Asset_versions`).
2. В базе my создать таблицы и четыре отчёта по контракту. Пока отчётов нет, кабинет работает: новые вкладки пустые.
3. Заполнить «Ссылка партнёра» для каждого партнёра (токены — случайные, как выдаёт `partner-links-admin.php`). После этого ссылки появятся во вкладке «Материалы и ссылки».
4. Проверить под партнёром: вкладки видны, ссылки открываются, «Копировать ссылку» кладёт адрес в буфер, у клиента в триале показан день из 14.

## Что не входит
- Прохождение экзамена в кабинете (вопросы, проверка ответов на сервере, попытки): вкладка «Обучение» показывает статус и ссылку на курс. Проверка ответов делается на сервере, ключ в браузер не отдаётся.
- Перенос событий скрипта `/m/<токен>` и бота в таблицы Интеграма.
- Блоки правил вывода (порог 500 ₽ во вкладке «Правила») не менялись и расходятся с офертой партнёра (1 000 ₽).
