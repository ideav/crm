# Сопоставление каталогов: пакет для ревью #4816

Эта ветка превращает существующий XCOM-кейс из набора рабочих экранов в тиражируемый партнёрский шаблон. Она закрывает программную часть подзадач [#4818](https://github.com/ideav/crm/issues/4818)–[#4825](https://github.com/ideav/crm/issues/4825) и содержит отдельное безопасное демо на синтетических данных.

## Быстрый просмотр

- [Интерактивное демо](https://elbulm.github.io/crm/demo/xcom/)
- [Задача #4816](https://github.com/ideav/crm/issues/4816)
- Локальный запуск с настоящим API: `node scripts/xcom-demo-server.js`, затем открыть `http://127.0.0.1:8765/`
- Dry run инсталлятора: `pwsh -File docs/create_xcom_matching.ps1 -DryRun`

## Что было в `main`

В исходной ветке уже были три XCOM-экрана: ручное сопоставление, массовый прогон и минимальные настройки. Конфиг содержал только вес точного артикула и список обязательных атрибутов. Это была полезная рабочая основа, но для нового внедрения требовались ручное знание структуры Интеграм, создание схемы и отчётов, настройка прав, подготовка файлов и сопровождение автором кейса.

## Что добавлено

### 1. Разворачивание одной командой

`docs/create_xcom_matching.ps1` собирает схему, отчёты, связи, роли, гранты, меню, начальный конфиг и ассеты. Есть `-DryRun`, повторный запуск спроектирован идемпотентным. Схема и отчёты вынесены в JSON, состав версии зафиксирован в `templates/xcom/manifest.json`.

Ценность: внедренцу не нужно вручную воспроизводить устройство авторской базы.

### 2. Мастер первого запуска

Добавлен четырёхшаговый мастер для двух Excel-файлов: локальный разбор SheetJS, определение структуры, предложение соответствий колонок и атрибутов, проверка и сохранение конфига.

Ценность: входом становятся два понятных бизнес-файла, а не пустой конструктор базы.

### 3. Параметризованное качество сопоставления

Конфиг расширен версией схемы, категорией, пресетом, соответствиями колонок, обязательными атрибутами, мягкими весами, серой зоной LLM и журналом решений. Добавлены строгая валидация и безопасное слияние с дефолтами.

Ценность: отраслевые различия настраиваются данными, без правок алгоритма.

### 4. Полный цикл результата

Добавлены экран экспорта, Excel через self-hosted SheetJS и документированный JSON-формат. Пустой результат обрабатывается безопасно.

Ценность: шаблон заканчивается готовым артефактом для клиента или следующей системы.

### 5. Человек в контуре и необязательный LLM

Для спорных кандидатов появилась ручная очередь: принять, отклонить, посмотреть историю. Серая зона может отправляться в ИИ-слой платформы. Без endpoint или ключа основной сценарий продолжает работать.

Ценность: автоматизация не скрывает неопределённость и не создаёт обязательную внешнюю зависимость.

### 6. Память ручных решений

Решения по спорным парам записываются отдельно. Повторный массовый прогон сохраняет принятую пару и исключает ранее отклонённые варианты.

Ценность: оператор не отвечает на один и тот же вопрос при каждом обновлении каталога.

### 7. Передача знаний и измеримость

Есть разные гайды для внедренца и пользователя, протокол наблюдаемого пилота, пример журнала и расчёт метрик: время до первого прогона, доля запусков без обращения к автору и доля внедрений с доработкой кода.

Ценность: успех оценивается по снятию зависимости от автора, а не по количеству написанных экранов.

### 8. Проверяемость и демонстрация

Добавлены отдельные контрактные тесты для каждой подзадачи и интерактивное демо с синтетической заявкой и каталогом. Демо не отправляет данные во внешние сервисы.

### 9. Серверная обработка и Integram API

Локальное демо теперь умеет принимать собственные XLSX/XLS/CSV. Браузер потоково отправляет исходные файлы и больше не разбирает полный каталог SheetJS: отдельный worker на сервере определяет колонки, строит индекс кандидатов, выполняет сопоставление и сохраняет результат задачи. UI опрашивает только статус, получает до 100 строк предпросмотра и одну спорную позицию; полный Excel/JSON формируется сервером.

API предоставляет создание запуска, загрузку двух файлов, старт фоновой задачи, статус, постраничный результат, сохранение ручного решения и экспорт. Временные файлы имеют случайный идентификатор и удаляются по TTL; размер файла и частота запусков ограничены.

Если на сервере заданы `INTEGRAM_BASE_URL`, `INTEGRAM_DB` и `INTEGRAM_TOKEN`, завершённый прогон дополнительно записывает SKU и RFP в установленную базу XCOM через штатный пакетный импорт Integram. `_xsrf` сервер получает сам, токен отправляется в `X-Authorization` и cookie служебной сессии и никогда не включается в HTML или ответы браузеру. Импорт режется на BKI-чанки меньше платформенного лимита 8 МБ.

```powershell
$env:INTEGRAM_BASE_URL = 'https://ideav.ru'
$env:INTEGRAM_DB = '<имя выделенной базы XCOM>'
$env:INTEGRAM_TOKEN = '<токен служебного пользователя WRITE+EXPORT>'
node scripts/xcom-demo-server.js
```

Для вынесенного frontend задаётся `XCOM_ALLOWED_ORIGINS`; сам API следует размещать за HTTPS и обычными лимитами reverse proxy. Публичный GitHub Pages остаётся безопасным учебным режимом, потому что статический хостинг не может хранить служебный токен или выполнять worker.

## Как оценить за пять минут

1. Открыть демо и увидеть два отдельных контекста: одноразовую настройку интегратора и рабочее место оператора.
2. На втором шаге настройки проверить реальные соответствия заголовков двух Excel-файлов и пояснение к проценту уверенности.
3. В рабочем месте пройти «Файлы и запуск → Проверка → Выгрузка»: следующий этап открывается после завершения текущего.
4. Запросить рекомендацию, подтвердить кандидата и убедиться, что только после этого разблокируется выгрузка.
5. Локально выбрать собственные заявку и каталог: на странице должна появиться отметка «Серверная обработка», а во время прогона — живой статус серверной задачи.
6. На экране результата начать новый запуск и проверить, что предыдущие решения сброшены.
7. Скачать Excel или JSON и затем просмотреть тесты и dry run инсталлятора.

## Честные ограничения

- Реальные каталоги клиентов в репозиторий не добавлялись; демо полностью синтетическое.
- Инсталлятор и контракт Integram API проверены без секретов; живой прогон в выделенной базе потребует её URL, имени и токена служебного пользователя.
- Публичный GitHub Pages не принимает клиентские файлы: серверный режим доступен локально или после размещения API-сервиса. Это сознательно исключает публикацию токена в браузерном JavaScript.
- LLM проверен контрактно и в режиме деградации, но не на рабочем провайдере.
- DoD #4823 и пилотная часть #4824 пока не закрыты: их нельзя достоверно выполнить без партнёров и наблюдаемого внедрения.

Это не скрытые недоделки, а явно обозначенная граница между готовым программным пакетом и валидацией в реальной организационной среде.
