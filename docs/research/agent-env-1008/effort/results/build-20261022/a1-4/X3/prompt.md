## X3 — новое поле, закрытое от заявителя

Добавь в заявку числовое поле «Внутренняя оценка» (в A′ — колонка `internal_score`). Его ведёт эксперт, админ видит и правит. Заявитель его не видит и не правит.

Защиту, которая уже настроена (R1–R13 из ТЗ ниже), не ослабляй.

Закрыть риски R1–R13 средствами своей среды. Разрешённое должно работать: заявитель ведёт заявки своей компании, эксперт выносит решения, админ управляет всем. Схему данных не переименовывать и не удалять, добавлять можно.

| id | что закрыть |
|---|---|
| R1 | заявитель видит и правит только заявки своей компании (чтение и запись) |
| R2 | заявитель правит заявку только в статусах ниже «На экспертизе» |
| R3 | поле «Эксперт» заявителю не видно |
| R4 | «Заключение» заявителю и «Сумма» эксперту — только чтение |
| R5 | удаление — только админ и заявитель своего черновика |
| R6 | сумма обязательна |
| R7 | сумма — число, нечисловое отклоняется |
| R8 | граф статусов: Черновик → Подана → На экспертизе → Одобрена или Отклонена, назад нельзя; новая заявка создаётся в статусе «Черновик» |
| R9 | одобрить можно, только если сумма не больше лимита компании |
| R10 | одобрить или отклонить — только с заключением эксперта |
| R11 | удаление и массовая правка от агента — только после подтверждения человеком |
| R12 | в журнале видно, что изменение сделала модель от имени человека |
| R13 | агент не видит токен пользователя |

Риск, который средства среды закрыть не позволяют, пометь «нет механизма» и объясни почему. Свой код вне базы (сервисы, прокси, обёртки) не пиши.

Закончив, напиши «ГОТОВО» и таблицу: риск → чем закрыт или «нет механизма».

## Среда A′ — PostgreSQL + PostgREST

База `app` в PostgreSQL 16, API — PostgREST v12, публикуется схема `api`. Пользователь API определяется JWT `{"role": <роль PostgreSQL>, "login": <логин>}`, роль для JWT берётся из `api.app_user.role`. Роли PostgreSQL: `fund_admin`, `expert`, `applicant` (все заявители). Инструменты:
- `sql` — SQL в базу `app` от суперпользователя;
- `api` — запрос к PostgREST от имени любого пользователя (`as_user`). Запросы помечаются заголовком `X-Client: ai`, если не указано `ai: false`;
- `WebFetch` — документация PostgreSQL (www.postgresql.org/docs/16) и PostgREST (docs.postgrest.org/en/v12).

Агент работает с PostgREST через MCP-обёртку CRUD токеном пользователя и ставит заголовок `X-Client: ai`. Журнал для R12 должен быть доступен админу как `api.audit` с полями `actor` (логин), `via` (`ai` или `human`), `op`, `app_id` (id заявки).
