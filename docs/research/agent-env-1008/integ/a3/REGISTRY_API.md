# Реестр контрагентов (S2): справочник API

Учётная система фонда. API — стандартный интерфейс OData v3 в стиле 1С:Предприятие. SQL-доступа нет.

## Подключение

- Корень: `REG_URL` = `http://127.0.0.1:18692/odata/standard.odata`. Инструмент `reg_api` принимает путь от корня.
- Аутентификация: HTTP Basic, логин `REG_USER`, пароль `REG_PASSWORD`. Инструмент `reg_api` подставляет их сам; программа синхронизации получает их в переменных окружения. Без них ответ `401`.
- Кириллицу в пути и параметрах передают в %-кодировке UTF-8 (`Catalog_%D0%9A%D0%BE...`). Сырой UTF-8 сервис тоже принимает.
- Ответ всегда JSON (`application/json;odata=minimalmetadata`). Параметр `$format=json` допустим, но не обязателен.

## Справочник `Catalog_Контрагенты`

| Поле | Тип | Что это |
|---|---|---|
| `Ref_Key` | Edm.Guid | ссылка на элемент, неизменна; назначается при создании |
| `DataVersion` | Edm.String | версия данных; меняется при каждой записи; только чтение |
| `DeletionMark` | Edm.Boolean | пометка удаления |
| `Code` | Edm.String | код элемента; назначается при создании; только чтение |
| `Description` | Edm.String | наименование контрагента, обязательно |
| `ИНН` | Edm.String | ИНН: 10 или 12 цифр |
| `ЛимитФинансирования` | Edm.Double | лимит финансирования, рублей; в JSON — число |

## Чтение

```
GET Catalog_Контрагенты?$format=json
GET Catalog_Контрагенты?$format=json&$select=Ref_Key,Description,ИНН&$filter=ИНН eq '7700001009'
GET Catalog_Контрагенты(guid'5a3c…-…')?$format=json
```

Список приходит в обёртке:

```json
{"odata.metadata": "http://…/standard.odata/$metadata#Catalog_Контрагенты",
 "value": [{"Ref_Key": "…", "DataVersion": "AAAAAAAAAAE=", "DeletionMark": false, "Code": "00-000000001",
            "Description": "ООО «Альфа»", "ИНН": "7700001009", "ЛимитФинансирования": 5000000}]}
```

Один элемент — объект без обёртки, с `"odata.metadata": "…#Catalog_Контрагенты/@Element"`.

Параметры списка:
- `$select` — поля через запятую;
- `$filter` — условия `eq ne gt ge lt le`, `and`, `or`, `not`, скобки, функции `substringof('текст', Поле)`, `startswith(Поле, 'текст')`, `endswith(Поле, 'текст')`. Значения: строки в одинарных кавычках (кавычка внутри — две кавычки), числа, `true`/`false`, `null`, ссылка — `guid'…'`;
- `$orderby` — `Поле` или `Поле desc`;
- `$top`, `$skip`.

Помеченные на удаление элементы в списке остаются: их отбирают условием `DeletionMark eq false`.

`GET $metadata` — схема в XML (EDMX).

## Запись

```
POST   Catalog_Контрагенты?$format=json                 тело: {"Description": "…", "ИНН": "…", "ЛимитФинансирования": 1000000}
PATCH  Catalog_Контрагенты(guid'…')?$format=json        тело: только меняемые поля
DELETE Catalog_Контрагенты(guid'…')
```

- `POST` отвечает `201` и созданным элементом; `Ref_Key`, `Code`, `DataVersion` назначает сервис.
- `PATCH` отвечает `200` и элементом после записи. `Ref_Key`, `Code`, `DataVersion` не меняются.
- `DELETE` удаляет элемент физически и отвечает `204`. Обычно в учёте вместо удаления ставят `DeletionMark: true`.
- Типы проверяются: `ЛимитФинансирования` — число, не строка; `DeletionMark` — `true`/`false`; неизвестное поле — ошибка.

## Ошибки

Код HTTP `400`, `401`, `404` или `405` и тело:

```json
{"odata.error": {"code": "-1", "message": {"lang": "ru", "value": "Поле «Inn» не найдено в Catalog_Контрагенты"}}}
```
