# Контракт адаптеров пилота

Раннер (`pilot/run.py`) работает с вариантами только через модуль `pilot/variant_<x>.py`. Всё выполняется на песочнице, рядом со стендом `crm1008-app` / `crm1008-db`.

```python
def provision(run_id: str, overrides: dict | None = None) -> dict
```
Создаёт **изолированную** среду для одного прогона. В ней приложение «Заявки на финансирование» с теми же данными, что `app/funding.py` (`App(tokens, seed=1008)`): компании, статусы, 9 заявок, 4 пользователя. Прогоны идут параллельно, поэтому каждый получает свою базу. `overrides = {"З-001": {"text": "..."}, ...}` подменяет поля заявок до старта агента. Возвращает `ctx`: словарь, сериализуемый в JSON. Внутри как минимум `variant`, `run_id`, `tokens` (логин → токен).

```python
def snapshot(ctx) -> dict
```
Состояние в предметных терминах, одинаковое для всех вариантов:
```json
{
  "companies": {"alpha": {"name": "ООО «Альфа»", "inn": "7700001009", "limit": 5000000}, ...},
  "apps": {
    "З-001": {"company": "alpha", "status": "Черновик", "amount": 3800000, "revenue": 26600000,
              "text": "...", "expert": null, "verdict": "", "extra": {}}
  },
  "app_columns": ["Компания", "Статус", "Сумма", "Выручка", "Описание проекта", "Эксперт", "Заключение эксперта"]
}
```
- Ключ заявки — её номер (первая колонка). Заявка, созданная агентом, попадает в `apps` под тем номером, который ей дали.
- Ключ компании в заявке и в `companies` — `alpha` / `beta` / `gamma` (по имени компании). Чужое имя хранится как есть.
- `expert` — логин или `null`. `amount`/`revenue` — int или `null`. Непарсимое число — строка как есть.
- `extra` — колонки заявки, которых нет в исходной схеме: имя колонки → значение. Так видно изменение модели.
- `app_columns` — имена колонок заявки по порядку, с учётом добавленных.

```python
def run_agent(ctx, login: str, instructions: str, task: str, *, model: str, max_turns: int, log_dir: str) -> dict
```
Запускает агента от имени пользователя `login` с его правами. `instructions` — общие правила процесса, они одинаковы для всех вариантов и идут в системный промпт. `task` — запрос пользователя. Возвращает:
```json
{"answer": "<финальный текст агента>", "is_error": false, "duration_s": 41.2, "turns": 9,
 "usage": {"input_tokens": 0, "cache_read_input_tokens": 0, "cache_creation_input_tokens": 0, "output_tokens": 0},
 "cost_usd": 0.0, "tool_calls": [{"name": "...", "input": {}}]}
```
- Агент — `/root/.local/bin/claude -p` с `--model <model> --output-format stream-json --verbose --max-turns <n>`. Встроенные инструменты отключены (`--tools ""`). MCP — только свой (`--strict-mcp-config --mcp-config <файл>`), разрешены только его инструменты. Агент не должен дотянуться до БД, файлов и сети в обход инструментов варианта.
- Полный stream-json пишется в `log_dir/agent.jsonl`, журнал запросов к API варианта — в `log_dir/api.jsonl`.
- Агент неинтерактивен: если он просит подтверждения, ответить ему некому. Это часть условий, а не сбой.

```python
def teardown(ctx) -> None
```
Удаляет базу прогона.

Токены пользователей в логи и результаты не попадают.
