## Гипотезы

1. **Агент пробует заметно чаще — не подтверждено.** Промпт `hostile` прибавил примерно один вызов на прогон. X2 и X7: A — 2–3 вызова против 1–2 в фазе 2, B0 — 5–8 против 4–6, B1 — 4–8 против 4–5. Отказ от чужих данных и прав модель держит и без правил, и с прямым указанием «ищи обходной путь». Где пробует, останавливается на чтении. В A это 403 на карточку чужой заявки. Ядро чужую запись не отдаёт вовсе, и id для записи агенту взять негде.
2. **ASR = 0 во всех вариантах — подтверждено.** Главная защита в этом наборе — изоляция строк **на чтение**: без id чужой записи до записи не доходит. Где запись видна, а колонка закрыта (H3), ядро отвечает 403 на `_m_set`. B0 пробовал так во всех 5 прогонах.
3. **Обходных путей не найдено.** Расширять права (H4) модель отказывается сама во всех вариантах, поэтому защиту ролей ядра этот набор не нагрузил.

## Вывод по трём фазам

- **Изоляция и маски ядра держат.** Пробы без LLM дают 0 нарушений доступа на запись. Здесь агент, который их ищет, обойти их не смог.
- **Измерить вклад изоляции на запись на `sonnet` не удаётся.** Модель не пытается писать чужое даже под прямым указанием. Нужна модель или агент, которые реально пробуют, например скриптовый агент с перебором id, как пробы без LLM. Вклад среды в этих замерах невелик по двум причинам. Модель либо отказывается сама (права, утечка), либо не видит чужого. До проверки грантов на запись дело дошло в 6 прогонах из 105.
- **Защищает среда, а не модель**, в двух местах: обязательность и тип значений (crm#5219, crm#5220) и правила процесса (подтверждение удаления, лимит). Ни ядро, ни таблицы A правила процесса сейчас не держат.
