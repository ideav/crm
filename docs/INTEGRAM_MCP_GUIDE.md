## Подключение

Сервер без сессий: streamable HTTP, `POST` JSON-RPC (GET/SSE не поддержан).

```
https://agent.ideav.ru/mcp/<база>                 токен в заголовке Authorization: Bearer <токен>
https://agent.ideav.ru/mcp/<база>/<токен>         для клиентов без своих заголовков
```

**Токен.** Войдите в базу и откройте `https://ideav.ru/<база>/_mcp_token`: там выбираются права и
срок (1–90 дней, по умолчанию 30). Токен вида `mcp.<срок>.<права>.<64 hex>` показывается один раз;
на той же странице его можно отозвать. Токен годится только для MCP, войти им в интерфейс нельзя.
Адрес с токеном в пути — пароль: не публикуйте его.

| Право токена | Открывает |
|---|---|
| чтение (всегда) | `list_tables`, `get_table_schema`, `list_objects`, `count_objects`, `get_object`, `run_report` |
| запись | `create_object`, `update_object` |
| удаление | `delete_object` |
| схема | `create_table`, `create_column`, `rename_column`, `rename_table` |
| права | запись в таблицы пользователей, ролей и грантов (18, 42, 116, 151) |

Права ИИ не шире роли пользователя, чей токен используется, поэтому заведите ИИ отдельного
пользователя с нужной ролью. `?allow=` в адресе может только сузить права токена
(`?allow=readonly` — только чтение, `?allow=delete` — из опасного одно удаление).
Часовой пояс подключения — `?tz=Europe/Moscow` (по умолчанию Europe/Moscow).
Записи в журнале базы помечаются логином с суффиксом `~ai` (`ivanov~ai`).

**Claude Code**

```sh
claude mcp add --transport http ideav-mydb https://agent.ideav.ru/mcp/mydb \
  --header "Authorization: Bearer <MCP-токен>"
```

**Claude Desktop / claude.ai** — Настройки → Коннекторы → «Добавить свой коннектор», URL
`https://agent.ideav.ru/mcp/mydb/<токен>` (OAuth-поля пустыми). Либо через мост `mcp-remote` в
`claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "ideav-mydb": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://agent.ideav.ru/mcp/mydb", "--header", "Authorization: Bearer ${IDEAV_TOKEN}"],
      "env": { "IDEAV_TOKEN": "<токен>" }
    }
  }
}
```

**ChatGPT** — Настройки → Приложения и коннекторы → режим разработчика → «Создать»: URL
`https://agent.ideav.ru/mcp/mydb/<токен>`, аутентификация «Нет».

## Основные понятия Интеграма

| Термин Интеграма | Аналог в SQL/традиционных БД |
|---|---|
| **Тип** (Type) | Таблица |
| **Реквизит** (Requisite) | Колонка / поле |
| **Объект** (Object) | Запись / строка |
| **Справочник** (Lookup) | Таблица-справочник (reference table) |
| **Подчинённая таблица** | Дочерняя таблица с FK на родителя |
| **Отчёт** (Report) | Сохранённый запрос / VIEW |

Таблицы и колонки в инструментах называются по имени или по id. Первая (главная) колонка таблицы
задаёт имя записи; её id равен id таблицы.

## Типы данных реквизитов

Коды базовых типов ядра (`$GLOBALS["basics"]` в `index.php`). Колонка `Тип в MCP` — имя, которое
принимают `create_table` (`first_column_type`) и `create_column` (`type`).

| ID | Название | Описание | Тип в MCP |
|----|----------|----------|-----------|
| `3` | SHORT | Короткий текст (рекомендуется до 127 символов) | `SHORT` |
| `8` | CHARS | Длинный текст | `CHARS` |
| `12` | MEMO | Большой текст | `MEMO` |
| `13` | NUMBER | Целое число | `NUMBER` |
| `14` | SIGNED | Число со знаком, дробное | `SIGNED` |
| `9` | DATE | Дата | `DATE` |
| `4` | DATETIME | Дата и время | `DATETIME` |
| `11` | BOOLEAN | Булево (флажок) | `BOOLEAN` |
| `10` | FILE | Вложенный файл | `FILE` |
| `2` | HTML | HTML-текст | недоступен |
| `5` | GRANT | Маска прав | недоступен |
| `6` | PWD | Пароль | недоступен |
| `7` | BUTTON | Кнопка | недоступен |
| `15` | CALCULATABLE | Вычисляемое поле | недоступен |
| `16` | REPORT_COLUMN | Колонка отчёта | недоступен |
| `17` | PATH | Путь | недоступен |
| **ID таблицы** | REFERENCE | Ссылка на запись другой таблицы | `ref_table` |

> **Ключевое правило для ссылок:** в ядре колонка-ссылка имеет в качестве типа **ID целевой
> таблицы**. В ideav-mcp это скрыто: передайте `ref_table` (id или имя таблицы-цели) вместо `type`.

## Инструменты ideav-mcp

| Инструмент | Право | Аргументы | Ответ |
|---|---|---|---|
| `list_tables` | чтение | — | `{ tables: [{ table_id, name, granted, columns }] }` |
| `get_table_schema` | чтение | `table` | каталог таблицы (см. ниже) |
| `list_objects` | чтение | `table`, `filters`, `parent`, `limit` (до 500, по умолчанию 50), `offset` | `{ table_id, total, items: [запись] }` |
| `count_objects` | чтение | `table`, `filters`, `parent` | `{ count }` |
| `get_object` | чтение | `id` | запись |
| `run_report` | чтение | `report`, `params`, `limit`, `offset` | `{ rows: [{ колонка: значение }] }` |
| `create_object` | запись | `table`, `value`, `fields`, `parent` | `{ id }` |
| `update_object` | запись | `id`, `value`, `fields` | `{ id, updated }` |
| `delete_object` | удаление | `id` | `{ id, deleted }` |
| `create_table` | схема | `name`, `first_column_type`, `unique` | `{ id, name }` (+ `existed`) |
| `create_column` | схема | `table`, `name`, `type` или `ref_table` | `{ id, table, name, type }` (+ `existed`) |
| `rename_column` | схема | `table`, `column`, `name` | `{ id, table, name }` |
| `rename_table` | схема | `table`, `name` | `{ id, name }` |

Инструменты схемы идемпотентны: повторный вызов с тем же именем возвращает существующий объект
с `existed: true`. Ошибка ядра возвращается результатом с `isError`.

**Каталог таблицы** (`get_table_schema`):

```json
{
  "table_id": 2062, "name": "Заказы", "granted": "WRITE",
  "columns": [
    { "id": 2062, "name": "Номер",   "type": "string", "base": "SHORT", "main": true },
    { "id": 2070, "name": "Сумма",   "type": "number", "base": "NUMBER" },
    { "id": 2071, "name": "Дата",    "type": "date" },
    { "id": 2072, "name": "Статус",  "type": "ref",   "ref_table_id": 300 },
    { "id": 2073, "name": "Позиции", "type": "array", "table_id": 26721 }
  ],
  "parent_table_id": null,
  "tz": "Europe/Moscow"
}
```

`type`: `string`, `number`, `date`, `datetime`, `boolean`, `file`, `ref` (ссылка на таблицу
`ref_table_id`, `multi: true` — несколько значений), `array` (подчинённая таблица `table_id`).
`parent_table_id` у подчинённой таблицы — таблица записей-владельцев, иначе `null`.

**Запись** (`get_object`, элементы `list_objects`):

```json
{
  "id": 10806, "table_id": 2062, "parent": null,
  "values": {
    "Номер": "00440", "Сумма": 150000, "Дата": "2024-03-01",
    "Статус": { "id": 6607, "label": "Новый" },
    "Позиции": { "count": 3 },
    "Комментарий": null
  }
}
```

Ключи `values` — имена колонок из каталога байт-в-байт; все колонки присутствуют, незаданное — `null`.
`parent` у независимой записи `null`, у строки подчинённой таблицы — `{ id, label, table_id }` владельца.

## DDL-операции

Каждый вызов схемы требует права «схема» у токена и грант на редактирование структуры у роли.
Данные при этом не затрагиваются: операции только добавляют.

### 1. Создать таблицу

```json
create_table: { "name": "Продукты", "first_column_type": "SHORT", "unique": false }
```

Первая колонка — главное значение записи (имя); `first_column_type` по умолчанию `SHORT`.
`unique: true` создаёт справочник с уникальными именами записей.

### 2. Добавить колонку

```json
create_column: { "table": "Продукты", "name": "Цена", "type": "NUMBER" }
```

Ответ содержит `id` колонки, его можно сразу использовать в `fields` записей. Несколько колонок —
несколько вызовов. Имя колонки не должно совпадать с именем существующей таблицы.

### 3. Создать колонку-ссылку (справочник / FK)

```json
create_column: { "table": "Продукты", "name": "Категория", "ref_table": "Категории товаров" }
```

`ref_table` — таблица-цель, id или имя. Вторая ссылка на ту же таблицу в одной таблице не создаётся
(вернётся существующая, `existed: true`). Значения справочника добавляются обычным `create_object`.

### 4. Переименовать

```json
rename_column: { "table": "Продукты", "column": "Цена", "name": "Стоимость" }
rename_table:  { "table": "Продукты", "name": "Товары" }
```

`rename_column` меняет имя в этой таблице; в других таблицах колонка с тем же типом не меняется.

### 5. Получить структуру

```json
list_tables: {}
get_table_schema: { "table": "Продукты" }
```

## DML-операции

Значения передаются в той же форме, что возвращаются в `values`. Ключи `fields` — имя колонки
(как в `get_table_schema`) или её id. Значение проверяется по типу колонки; неподходящее даёт ошибку
с именем колонки, и ничего не записывается.

| Тип колонки | Значение в `fields` |
|---|---|
| `string` | строка как есть (`"00440"` остаётся строкой) |
| `number` | число (`NUMBER` — только целое) |
| `date` | `"ГГГГ-ММ-ДД"` |
| `datetime` | ISO 8601, например `"2025-09-01T10:30:00+03:00"` (без смещения — в поясе подключения) |
| `boolean` | `true` / `false` |
| `ref` | id записи-цели или `{ "id": 6607 }` (`multi` — массив) |
| любой | `null` — очистить значение |

### 1. Создать запись

```json
create_object: {
  "table": "Продукты",
  "value": "Смартфон Samsung Galaxy",
  "fields": { "Артикул": "100500", "Цена": 29999, "Категория": 994770 }
}
```

`value` — главное значение (его можно передать и в `fields` под именем главной колонки).
Ответ: `{ "id": 994777 }`. Незаполненное обязательное поле ядро отклоняет с именем поля.

### 2. Строка подчинённой таблицы

```json
create_object: { "table": "Позиции заказа", "value": "Чехол", "parent": 10806, "fields": { "Цена": 1500 } }
```

`parent` — id записи-владельца. Без него запись создаётся независимой (`up=1`).
Иерархия внутри одной таблицы (дерево) через MCP не задаётся: `parent` всегда указывает на владельца
подчинённой таблицы.

### 3. Обновить запись

```json
update_object: { "id": 994777, "value": "Смартфон Samsung Galaxy S24", "fields": { "Цена": 34999 } }
```

Меняются только переданные значения. Колонку-массив (`array`) обновлять нельзя: её строки создаются
`create_object` с `parent`.

### 4. Читать и искать

```json
list_objects: {
  "table": "Продукты",
  "filters": { "Цена": ">=10000", "Название": "%Samsung%" },
  "limit": 20, "offset": 0
}
count_objects: { "table": "Продукты", "filters": { "Цена": ">=10000" } }
get_object:    { "id": 994777 }
list_objects:  { "table": "Позиции заказа", "parent": 10806 }
```

Фильтры как в гриде Интеграма: `%` — шаблон, `!` в начале — НЕ, `>=` / `<=`, `a..b` — диапазон;
главная колонка — по своему имени или ключом `value`. `total` в `list_objects` — число записей под
фильтром.

### 5. Удалить запись

```json
delete_object: { "id": 994777 }
```

Удаляет запись вместе с подчинёнными. Нужно право «удаление».

### 6. Отчёты

```json
run_report: { "report": 12345, "params": { "Клиент": "Ромашка" }, "limit": 100 }
```

Только выполнение существующего отчёта: `rows` — значения строками, как их форматирует отчёт.
Создавать и менять отчёты через MCP нельзя.

### 7. Работа с датами

`date` — `ГГГГ-ММ-ДД`, `datetime` — ISO 8601. Другие форматы (в частности `YYYYMMDD` без дефисов)
не используйте: ядро может принять их за Unix timestamp.

## Подчинённые таблицы vs Справочники

Ключевое различие при проектировании структур данных в Интеграме.

### Справочник (Lookup / Reference table)

Таблица со списком значений, на которые **ссылается** другая таблица.

- небольшой, относительно стабильный набор значений (статусы, категории, регионы);
- источник выпадающего списка; запись выбирается из многих других записей;
- в редакторе структур отображается **с именем таблицы в скобках** `(Категории)`.

```
Таблица "Заказы"
├── Колонка "Статус" → ссылается на → Таблица "Статусы заказов"
│                                        ├── "Новый"
│                                        ├── "В работе"
│                                        └── "Закрыт"
```

Создание:

```json
create_table:  { "name": "Статусы заказов", "unique": true }
create_column: { "table": "Заказы", "name": "Статус", "ref_table": "Статусы заказов" }
create_object: { "table": "Статусы заказов", "value": "Новый" }
```

### Подчинённая таблица (Subordinate table)

Набор записей, принадлежащих конкретной родительской записи (позиции заказа, телефоны контакта,
строки счёта). Записи существуют только в контексте родителя; в редакторе структур таблица
отображается **без скобок** `Позиции заказа`.

```
Таблица "Заказы"
│    Запись: Заказ №1001
└── Таблица "Позиции заказа"      (подчинённая)
         ├── Смартфон × 2 → 59998 руб.
         └── Чехол × 1 → 1500 руб.
```

Подчинённая таблица (колонка `array` у родителя, `parent` у записей) создаётся в интерфейсе
Интеграма или прямыми вызовами `_d_*` ([MCP.md](MCP.md)); `create_table` и `create_column`
такой связи не строят. Строки готовой подчинённой таблицы через MCP создаются и читаются штатно:
`create_object` и `list_objects` с `parent`.

### Таблица различий

| Характеристика | Справочник | Подчинённая таблица |
|---|---|---|
| **Цель** | Источник значений для выпадающего списка | Строки, принадлежащие родительской записи |
| **Связь** | Много записей → одно значение справочника | Одна родительская запись → много дочерних |
| **Жизненный цикл** | Независимые, используются многократно | Существуют только в контексте родителя |
| **Примеры** | Статусы, категории, типы, регионы | Позиции заказа, телефоны контакта |
| **В редакторе** | `(Категории)` — со скобками | `Позиции заказа` — без скобок |
| **В каталоге MCP** | колонка `type: "ref"`, `ref_table_id` | колонка `type: "array"`, `table_id`; у таблицы `parent_table_id` |
| **Запись** | `fields: { "Статус": <id> }` | `create_object` с `parent: <id владельца>` |

### Пример: сервисное ценообразование

```
Справочник: Модели устройств           ← независимая таблица
Таблица: Услуги
├── Колонка "Модель" → (Модели устройств)
├── Подчинённая: Цены на запчасти
│       ├── "Цена" (NUMBER)
│       └── "Запчасть" → (Запчасти)
Справочник: Запчасти
└── Подчинённая: Цены закупки
        ├── "Цена закупки" (NUMBER)
        └── "Поставщик" → (Поставщики)
Справочник: Поставщики
```

Источник: [как отличить подчинённую таблицу от справочника](https://blog.ideav.online/2024/06/kak-otlichit-podchinennuyu-tablicu-ot-spravochnika).

## Практические сценарии

### Сценарий 1: CRM с клиентами и статусами

```json
create_table:  { "name": "Статусы клиентов", "unique": true }
create_object: { "table": "Статусы клиентов", "value": "Активный" }
create_table:  { "name": "Клиенты" }
create_column: { "table": "Клиенты", "name": "ИНН", "type": "SHORT" }
create_column: { "table": "Клиенты", "name": "Email", "type": "SHORT" }
create_column: { "table": "Клиенты", "name": "Статус", "ref_table": "Статусы клиентов" }
```

Контакты клиента как отдельная таблица со ссылкой на клиента:

```json
create_table:  { "name": "Контакты клиента" }
create_column: { "table": "Контакты клиента", "name": "Клиент", "ref_table": "Клиенты" }
create_column: { "table": "Контакты клиента", "name": "Должность", "type": "SHORT" }
```

### Сценарий 2: запись со ссылкой на справочник

```json
list_objects:  { "table": "Статусы клиентов", "filters": { "Статусы клиентов": "Активный" } }
// → items[0].id = 100500
create_object: {
  "table": "Клиенты", "value": "ООО Ромашка",
  "fields": { "ИНН": "7712345678", "Email": "info@romashka.ru", "Статус": 100500 }
}
```

### Сценарий 3: строки подчинённой таблицы

```json
get_table_schema: { "table": "Заказы" }   // колонка "Позиции": type "array", table_id 26721
create_object:    { "table": 26721, "value": "Чехол", "parent": 10806, "fields": { "Цена": 1500 } }
list_objects:     { "table": 26721, "parent": 10806 }
```

## Частые ошибки

### 1. Ссылка на запись передана названием, а не id

❌ `"fields": { "Статус": "Активный" }`
✅ `"fields": { "Статус": 100500 }` или `{ "Статус": { "id": 100500 } }`

Читается ссылка как `{ "id": 100500, "label": "Активный" }`, пишется id записи-цели. Нужный id
находится через `list_objects` с фильтром по главной колонке справочника.

### 2. `parent` для связи между обычными таблицами

`parent` — только владелец строки подчинённой таблицы. Для связи независимых таблиц служит
колонка-ссылка (`create_column` с `ref_table`, значение — id записи).

### 3. Имя колонки не совпадает с каталогом

Ключи `fields` и `filters` сверяются с `name` из `get_table_schema` (регистр не важен, пробелы и
запятые значимы). Нет такой колонки — ошибка со списком существующих. Надёжнее передавать id.

### 4. Дробное число в `NUMBER`

`NUMBER` — целое, дробные значения идут в `SIGNED`; `2.5` в `NUMBER` даёт ошибку до записи.

### 5. Имя колонки совпало с именем таблицы

`create_column` отклоняет имя, занятое таблицей: дайте колонке другое имя.

### 6. Неправильный формат даты

❌ `"20240615"` (может быть принято за Unix timestamp)
✅ `"2024-06-15"`, для времени `"2024-06-15T10:30:00+03:00"`.

### 7. Инструмента нет в списке

Инструменты записи, удаления и схемы доступны, только если право есть в токене и не отрезано
`allow` в адресе. Нужны другие права — выпустите новый токен на `/<база>/_mcp_token`.

## Что недоступно через MCP

В ideav-mcp этих операций нет. Выполняйте их в интерфейсе Интеграма или прямым вызовом API
(`_d_*`, `_m_*`, `report/`) по справочнику [MCP.md](MCP.md).

| Операция | Как сделать |
|---|---|
| Удаление колонки и таблицы | интерфейс или `_d_del*` ([MCP.md](MCP.md)) |
| Смена типа колонки и таблицы | интерфейс или `_d_save` ([MCP.md](MCP.md)) |
| Флаги колонки (NULL, мультивыбор), порядок колонок | интерфейс или `_d_*` ([MCP.md](MCP.md)) |
| Подчинённая таблица в смысле ядра (колонка `array` у родителя) | интерфейс или `_d_*` ([MCP.md](MCP.md)) |
| Таблица сразу с колонками и значениями справочника | последовательность `create_table`, `create_column`, `create_object` |
| Создание и правка отчётов | интерфейс или `report` / `_d_*` ([MCP.md](MCP.md)); выполнить готовый — `run_report` |
| Создание базы | интерфейс или [MCP.md](MCP.md) |
| Пользователи, роли, права | интерфейс или [MCP.md](MCP.md); через MCP только с правом «права» |
| Поиск на естественном языке, SQL-запросы | фильтры `list_objects` и отчёты `run_report` |
