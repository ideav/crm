# Перенос базы со старого Интеграма в новый

Процедура переносит базу `<db>` со старого Интеграма (integram.io, ядро
`experiments/index_integram.io.php`) на новый (ядро `index.php` этого репозитория).
Инструмент — `migrate.js`, зависимостей нет, нужен Node 18+.

## Чем отличаются ядра

| | Старое ядро | Новое ядро |
|---|---|---|
| Длинное значение | первые 127 символов в строке, остаток — кусками по 127 в строках `t=0, up=<id>, ord=0,1,…`; хвостовые пробелы кусков срезаны MySQL | целиком в одной строке, `val MEDIUMTEXT utf8mb4` |
| Меню (запрос `MyRoleMenu`) | плоский список, колонки `Name`, `HREF` | дерево, колонки `menu_id`, `menu_up`, `name`, `href`, `icon` (`templates/main.html`, блок `MyRoleMenu`) |
| Кука токена | `<db>=<токен>` | `idb_<db>=<токен>` |
| Хеш пароля | `sha1(SALT . strtoupper(логин) . db . пароль)` | `sha512(SALT . db . пароль)` |

Запросы (тип 22, колонки 28, связи 44), их плейсхолдеры (`[USER_ID]`, `[TODAY]` …) и адреса
`report/<id>` в обоих ядрах одинаковы — после склейки хвостов запросы работают без правки.
Файлы лежат в `templates/custom/<db>/` и `download/<db>/` и в обоих ядрах доступны через
`/<db>/dir_admin/`.

## Шаги

### 1. Таблица базы

Скопировать таблицу `<db>` с сервера MySQL старого Интеграма на сервер нового (например,
`mysqldump <схема> <db> | mysql <схема>`), затем склеить хвосты:

```bash
node tools/old-integram-migration/migrate.js sql --db <db> > merge-tails.sql
mysql <схема> < merge-tails.sql
```

Скрипт переводит `val` в `MEDIUMTEXT utf8mb4`, собирает каждое значение из строки и её хвостов
(каждый кусок, кроме последнего, дополняется пробелами до 127 символов — как читало старое ядро в
`Get_tail`) и удаляет строки `t=0`. Повторный запуск ничего не меняет.

Индексы, на которые рассчитано новое ядро: `up_t (up, t)`, `t_up (t, up)`, `t_val (t, val(191))`,
`up_ord (up, ord)` (`docker/mysql/010-integram-bootstrap.sql`) — добавить недостающие.

### 2. Файлы

```bash
node tools/old-integram-migration/migrate.js files \
  --old https://integram.io/<db> --old-token <токен старой базы> \
  --new https://<сервер>/<db> --new-token <токен новой базы> [--apply]
```

Копирует `templates/custom/<db>/` и `download/<db>/` со всеми подкаталогами байт-в-байт.
Не копируются:
- каталоги `logs` и `backups`;
- шаблоны корня `templates/custom/<db>/`, одноимённые общим шаблонам нового ядра
  (`templates/*.html` репозитория, прежде всего `main.html`): такой файл перекрыл бы новую
  версию. `--keep-overrides` копирует и их.

`dir_admin` создаёт каталоги в нижнем регистре — о каталогах с заглавными буквами инструмент
предупреждает, ссылки на них нужно поправить.

### 3. Меню

```bash
node tools/old-integram-migration/migrate.js menu --new https://<сервер>/<db> --new-token <токен> [--apply]
```

Доводит запрос `MyRoleMenu` до колонок нового меню: переименовывает `Name` → `name`,
`HREF` → `href`, создаёт недостающие `menu_id` (функция `abn_ID`), `menu_up` (`abn_UP`) и
`icon` (реквизит 391 «Иконка», формат HTML). Колонка `icon` не создаётся, если у таблицы «Меню»
нет реквизита 391. Затем перечисляет пункты меню, которые новое меню не покажет как есть: с
`[USER_ID]` в адресе (новое меню его не подставляет) и с апострофом в адресе.

Перед записью инструмент сверяет колонки запроса с реквизитами типа 28 из `metadata`; при
расхождении правка отменяется целиком.

### 4. Пользователи

Хеши паролей старого ядра новое ядро не принимает: пользователям нужно задать пароли заново
(сброс пароля или правка администратором). Токены (реквизит 125) хранятся открыто и продолжают
работать — ими пользуются шаги 2–3.

Без `--apply` команды `files` и `menu` только печатают, что сделают.
