# Перенос баз со старого Интеграма

Инструкция для клиента, у которого на своём сервере уже работает старый Интеграм. Базы
(рабочие области) со старого сервера переносятся в эту установку нового Интеграма. Старый сервер
при этом не меняется.

Что переносится:

- **данные** — все типы, записи, запросы, роли, пользователи и их токены API;
- **файлы базы** — шаблоны рабочих мест (`templates/custom/<база>`) и загруженные файлы
  (`download/<база>`);
- **меню** — переводится в формат нового ядра.

**Пароли пользователей не переносятся.** Новое ядро хранит пароли иначе, и пароли со старого
сервера не подходят. После переноса администратор задаёт пароли заново.

## 1. На старом сервере: дамп и архив файлов

Узнайте имя схемы MySQL старого Интеграма: оно указано в `include/connection.php`, четвёртым
параметром `mysqli_connect(...)`. Каждая база Интеграма хранится в этой схеме отдельной таблицей
с тем же именем, что и база в адресе (`https://сервер/r7ohr` → таблица `r7ohr`).

Снимите дамп. Можно всей схемы, можно только нужных таблиц:

```bash
mysqldump --single-transaction --default-character-set=utf8mb4 -u <пользователь> -p <схема> | gzip > old.sql.gz
# или только нужные базы:
mysqldump --single-transaction --default-character-set=utf8mb4 -u <пользователь> -p <схема> r7ohr sales | gzip > old.sql.gz
```

Нужен обычный дамп таблиц: без `--no-create-info`, без представлений и процедур.

Упакуйте файлы баз. Команду выполняйте из корня сайта, где лежит `index.php`:

```bash
cd /путь/к/сайту
tar czf old-files.tgz templates/custom/r7ohr download/r7ohr
```

Для нескольких баз перечислите их папки в одной команде.

Скопируйте `old.sql.gz` и `old-files.tgz` на сервер нового Интеграма.

## 2. На новом сервере: перенос

Сначала установите новый Интеграм по [УСТАНОВКА-DOCKER.md](УСТАНОВКА-DOCKER.md) и проверьте, что
он открывается.

Затем из папки установки (там, где `compose.yaml`) посмотрите, какие базы есть в дампе:

```bash
bash local/import-old-db.sh --dump old.sql.gz
```

Скрипт выведет таблицы баз с числом строк и пользователей. `my`, `ru`, `en` — служебные
таблицы старой установки, их переносить не нужно.

Перенесите нужные базы:

```bash
bash local/import-old-db.sh --dump old.sql.gz --db r7ohr,sales --files old-files.tgz
```

Для каждой базы скрипт:

1. загружает таблицу базы из дампа;
2. приводит данные к формату нового ядра: склеивает длинные значения, которые старое ядро
   хранило кусками по 127 символов;
3. раскладывает файлы базы из архива. Шаблоны с именами общих шаблонов нового ядра
   (`main.html`, `info.html` и т. п.) не копируются: иначе они заменили бы новые. Журналы
   (`logs`) и архивы бэкапов (`backups`) тоже не копируются. В шаблоны на jQuery дописывается
   подключение jQuery;
4. переводит меню в формат нового ядра.

**База, которая уже есть в новой установке, не перезаписывается:** скрипт остановится. Служебные
таблицы новой установки (`my`, `ru`, `en`) дамп тоже не затрагивает: таблицы дампа загружаются
под временными именами, а лишние в конце удаляются.

### Установка без Docker

Скрипт `scripts/import-old-integram.sh` выполняется прямо на сервере. Нужны `mysql`, `node`
(версии 18 или новее) и `php`:

```bash
. /etc/apache2/envvars        # переменные INTEGRAM_DB_* и INTEGRAM_MASTER_PASSWORD
bash scripts/import-old-integram.sh --dump old.sql.gz --db r7ohr --files old-files.tgz \
     --webroot /var/www/integram --url http://localhost --server-name localhost
```

`--url` — адрес, по которому сайт открывается с самого сервера. `--server-name` — имя сайта в
этом адресе.

## 3. После переноса

1. Откройте `https://<сервер>/<база>`. Войдите под логином `admin` с мастер-паролем установки.
2. Задайте пароли пользователям: вручную в разделе «Пользователи» или всем сразу командой
   `bash local/reset-passwords.sh r7ohr`. Она задаёт каждому пользователю базы случайный пароль
   и сохраняет список «логин — пароль» в файл `passwords-r7ohr-<дата>.txt` в папке установки.
   Раздайте пароли и удалите файл. Токены API, которые были в старой базе, продолжают работать.
3. Откройте рабочие места базы и проверьте их. Если какое-то рабочее место опиралось на общий
   шаблон старого ядра (он не переносится), пришлите нам его название.

## Если что-то пошло не так

Скрипт останавливается строкой `СТОП: …`; пришлите её нам текстом. Перенос базы можно повторить:

```bash
docker compose --env-file .env.local exec db mariadb -u root -p ideav -e "DROP TABLE r7ohr"
```

Эта команда удаляет перенесённую базу из новой установки. После неё запустите
`local/import-old-db.sh` заново.
