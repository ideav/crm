# Коннектор источников данных → Интеграм

Универсальный коннектор. Код общий для всех проектов, всё проектное лежит в JSON-конфиге ([CONFIG.md](CONFIG.md)).
Источники подключаются адаптерами (`src/Source.php`): Битрикс24 и 1С через стандартный OData.
PHP 7.2+ (проверено на 7.4), расширения `curl`, `json`, `mbstring`. Composer не нужен.

```
connector/
├── b24ig.php                  точка входа (CLI)
├── config/<проект>.json       конфиг проекта
├── src/
│   ├── Util.php               лог, блокировка, состояние, исключения
│   ├── Http.php               curl
│   ├── Source.php             интерфейс источника и фабрика подключений
│   ├── Bitrix24Source.php     адаптер Битрикс24: фильтры, постраничность, поля, справочники
│   ├── BitrixClient.php       REST-клиент Битрикса
│   ├── OneCSource.php         адаптер 1С (OData): $metadata, $top/$skip, период, пустые GUID и даты
│   ├── ODataClient.php        HTTP-клиент OData 1С (Basic)
│   ├── IntegramClient.php     API Интеграма + схема таблицы из metadata
│   ├── Bki.php                формат импорта и разбиение на файлы
│   ├── Transform.php          справочники и преобразования полей
│   ├── EntitySync.php         загрузка одной сущности
│   └── Runner.php             оркестрация, отчёт, уведомления
├── tools/validate_config.py   проверка конфига по живой схеме
└── tests/                     модульные и живой тест (MockBitrix)
```

## Запуск

```bash
export B24_WEBHOOK='https://<портал>/rest/<user>/<код>/'   # только чтение CRM, задач, пользователей, отделов
export INTEGRAM_TOKEN='<токен учётки с WRITE+EXPORT на целевые таблицы>'

php b24ig.php --config=config/sportzania-spz.json --check                         # проверить схемы
php b24ig.php --config=config/sportzania-spz.json --dry-run --bki-dir=/tmp/bki    # собрать файлы, ничего не писать
php b24ig.php --config=config/sportzania-spz.json --allow-mass-create             # первая загрузка
php b24ig.php --config=config/sportzania-spz.json                                 # обычный запуск
php b24ig.php --config=config/sportzania-spz.json --only=leads,deals
php b24ig.php --config=config/sportzania-spz.json --reset=leads                   # начать инкремент заново
```

Коды выхода: `0` — успех, `1` — были ошибки (подробности в логе и `logs/<проект>/last-report.json`), `2` — неверный запуск.

### На сервере Интеграма: запуск по URL и cron
Выкладка — через `update.conf` (раскладку для `ideav/crm` собирает `tools/build-crm.sh`, строки — в `docs/b24ig/update.conf.snippet`):
```
b24ig.php       : /var/www/www-root/data/www/ideav.ru/
include/b24ig/* : /var/www/www-root/data/www/ideav.ru/include/b24ig/
```
Файлы базы лежат в её папке `templates/custom/<база>/connector/` (снаружи закрыта, владелец видит через `dir_admin`):

| Файл | Что это |
|---|---|
| `<имя>.json` | конфиг; `target.db` обязан совпадать с базой |
| `secrets.json` | значения для `${…}`, если их нет в окружении: `{"INTEGRAM_TOKEN": "…", "B24_WEBHOOK": "…"}` |
| `state/…`, `logs/…` | состояние загрузки и логи: пути из `runtime` считаются от этой папки |

```cron
# cron на сервере Интеграма — вызов по URL
0 * * * * curl -s "https://ideav.ru/b24ig.php?db=spz&config=sportzania-spz" >/dev/null
```
```bash
# первая большая загрузка — из командной строки, под пользователем сайта (чтобы state и logs принадлежали ему)
sudo -u www-root php /var/www/www-root/data/www/ideav.ru/b24ig.php --db=spz --config=sportzania-spz --allow-mass-create
```
- По URL из опций принимаются только `only`, `dry_run`, `check`; `JSON` — ответ отчётом в JSON вместо лога. Массовое создание, сброс состояния и пути — только из командной строки.
- Имена базы и конфига — по маске `[A-Za-z0-9_-]`: прочитать чужой файл через URL нельзя.
- Ответ: `200` — успех, `500` — ошибки загрузки (в отчёте), `400` — неверные параметры или конфиг, `409` — предыдущий запуск ещё идёт.
- Предел веб-запроса на сервере ~600 с: если запуск в него упрётся, следующий продолжит с сохранённого места.
- Имя базы стоит в строке запуска (`db=spz`) — по нему ядро будет показывать задачи cron базы.

### Проект в папке коннектора
```bash
B24_WEBHOOK=... INTEGRAM_TOKEN=... php b24ig.php --config=config/sportzania-spz.json
```
Параллельный запуск блокируется файлом `runtime.lock_file`: если прошлый запуск ещё идёт, новый сразу выходит.

## Что делает за один запуск

Сущности обрабатываются в порядке `order` из конфига. Для каждой:
1. **Проверка схемы.** Сверяет с metadata Интеграма колонки, ключ уникальности, признаки ссылки и multi. Сверяет с описанием полей Битрикса (`*.fields`) нужные поля. При расхождении сущность не загружается.
2. **Снимок таблицы в Интеграме** по внешнему ключу.
3. **Чтение Битрикса.**
   - `full`: всё.
   - `incremental`: сначала новые (`>ID` от курсора), затем изменённые с прошлого успешного прогона (`>DATE_MODIFY`, `<=ID`).
4. **Строки импорта в порядке колонок таблицы**, с `;` в конце.
   - Если ключа нет в таблице, старая запись без ключа привязывается по названию (`bind_existing`). Неоднозначные случаи уходят в отчёт на ручную привязку.
   - `insert_only`: существующие записи не трогаются.
   - Ссылка на несуществующую цель остаётся пустой, заглушка не создаётся.
5. **Импорт** файлами до 7 МБ / 5000 строк. Курсор инкремента сдвигается только после успешного файла.
6. **Второй проход ссылок по id** через `_m_set`: ссылки на ключевые колонки, мультиссылки, самоссылки (родитель), цели с дублями.
7. **Сверка:** все отправленные ключи должны найтись. Если нет — курсор откатывается, запуск завершается с ошибкой.

## Тесты

```bash
# модульные, без сети
docker run --rm -v "$PWD":/app -w /app php:7.4-cli php tests/unit.php

# запуск на сервере Интеграма: раскладка ideav/crm + встроенный веб-сервер PHP + spz
docker run --rm -v "$PWD":/app -w /app -e INTEGRAM_TOKEN php:7.4-cli php tests/web_test.php

# живой 1С: spz + имитация OData 1С; сам создаёт и удаляет временные таблицы «ТЕСТ1С …»
docker run --rm -v "$PWD":/app -w /app -e INTEGRAM_TOKEN php:7.4-cli php tests/live_1c_test.php

# живой: настоящая база spz + имитация Битрикса; пишет тестовые записи и удаляет их
docker run --rm -v "$PWD":/app -w /app -e INTEGRAM_TOKEN php:7.4-cli php tests/live_spz_test.php

# проверка конфига по живой схеме
INTEGRAM_TOKEN=... python3 tools/validate_config.py config/sportzania-spz.json
```

Живой тест проверяет:
- первую загрузку всех 6 сущностей: привязку старого отдела, неоднозначные имена родителей, `insert_only` в «Табельный», мультиссылки, справочники, экранирование, даты;
- повторный запуск без изменений: 0 новых записей, 0 правок;
- пробный запуск: ничего не пишется, состояние не двигается;
- изменения в источнике: переименование без дубля, замену мультиссылки, фазу изменённых;
- уборку до исходного числа записей.

## Известные ограничения v1
- 1С проверена только на имитации OData (живой базы нет): форматы полей конкретной конфигурации подтвердить на `--check` и `--dry-run`.
- Регистры 1С (остатки, обороты) пока не поддержаны: нет ключа записи.
- Если ссылка в источнике очищена (например, у отдела убрали родителя), в Интеграме она не очищается: пустое значение при импорте означает «не трогать».
- Записи, удалённые в Битриксе, в Интеграме остаются (`on_source_delete: keep`).
- Проверка полей Битрикса работает для `crm.*.list` и `tasks.task.list`. У `user.get` и `department.get` описания пользовательских полей нет, поэтому для них проверка не выполняется.
- С живым Битриксом не проверено (нет вебхука): формат полей `LINK`, `TAGS`, приоритета задач нужно подтвердить на первом `--check` и `--dry-run`.
